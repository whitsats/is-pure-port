# 真实选项、分支和跨剧本流程验证

## 选项处理规律

在 `MAC_001.bin:0x3878` 的三选项样本中，原指令把可见选项的**原表下标**保存到 UI 行，选择后写入 `0x6007`；其后的 `reg_calc` 复制到 `0x6000`，再由 `if` 决定目标。在隔离内存中执行原选项处理函数、操作数读写函数和 UI 行构造函数，注入三个选择位置，得到 0、1、2；另构造隐藏中间选项的两组输入，得到的两个 UI 行保留原表下标 0、2，选第二个可见项时写入 2。构造全部隐藏的输入时，写入原始选项数 3。证据和各次桩调用见 `数据/选项处理原指令对照_含全隐藏.json`。

选项绘制、点击与部分辅助函数在试验中用桩替代；这是原指令级验证，不是原游戏中实际逐项点击的录像。样本是 `0x72`，不把这条规则无条件推广到含随机排序的其他选项类型。此前扫描出的 59 组 `0x72` 和 153 条记录可复用此结构，但各项显示条件、文本来源、特殊分支和进入时的状态仍需核查。

`转换器/mac_choice.py` 将本规律整理成可复用的条件规划函数：按调用者给定的状态判断显示条件，保留原表下标、目标和原始参数；三项全隐藏时返回原始数量。状态未知时不能默认其值已经确认；尚未把所有条件选项接入正式 WebGAL 剧本。

`转换器/批量核查选项规划.py` 对静态清单批量复核：59/59 组选项、153/153 项原始序号及跳转目标与清单一致，其中 142 项条件是立即数、9 项依赖状态字、2 项依赖状态位。报告 `数据/批量选项规划_零状态试验.json` 对所有条目以零状态求值，只说明工具能处理这些结构，不代表实际游戏中有多少项显示。

## 状态与三条剧情

原游戏操作数写入函数的 `0x115870–0x115934` 根据写入值最低位设置或清除目标位；状态字和位使用相同的底层字节，存在别名。新状态模型实现了该规律，写位和字节别名已做单元测试，并用即时存档的内存副本执行原读写机器码，与模型对照 20 项，见 `数据/快照状态读写指令对照_含位写入.json`。这不证明本样片所假设的零初始状态符合真实游戏。

从 `0x3884` 的真实复制和判断指令开始，为每个选项写入对应返回值，其他状态假定为零：

| 选项 | 目标 | 实际导出对白 | 共同停止点 |
|---|---:|---:|---|
| 道歉 | `0x38C4` | 124 句 | `MAC_001:0x51E4 ext_goto` |
| 少扯了！ | `0x3C2C` | 107 句 | 同上 |
| ………… | `0x40B8` | 95 句 | 同上 |

`生成真实选项分支样片.py` 从原脚本、已确认的 v7.4 文本及语音清单生成 `选项分支真实剧情样片`，同时写出逐条源偏移、条件、状态写入和停止原因。浏览器无头检查三条路线，分别核对 125、108、96 行（包含各自结束提示），相关语音资源均成功加载，无页面脚本错误。两个未使用的可选 Live2D 库请求返回 404，测试将其单独记录，不当作游戏资源成功。

## 跨剧本

现有即时存档内，组 0 运行时名称表前 45 项与原盘 `MAC.AFS` 中同编号名称全部一致（`数据/跨剧本名称表快照核查.json`）；相邻的 45 只是条目数候选。存档当前的加载模式为 1，实际执行 `0x12D810` 分派时，资源编号 0、1、2、44 分别把组 0 与同编号传给 `0x101BF0`（`数据/跨剧本加载分派指令对照.json`）。底层读取函数在实验中是桩，这不是完整原机加载。

进一步执行到 `0x101BF0` 的异步请求构建：对相同四个编号，实际队列记录中的归档名为 `mac.afs`，条目编号分别为 0、1、2、44，见 `数据/跨剧本读取请求指令对照_字段修正.json`。Unicorn 不支持其中一条 R5900 三操作数乘法，该条以等价算术模拟；后续异步读盘及解压没有执行。早期同名无“字段修正”后缀的报告误称一个参数为长度，应以修正版中性字段为准。

`生成真实选项分支样片.py --cross` 从每条分支各自的转换状态继续解释目标 `MAC_002:0x0C`，并生成三份 WebGAL 目标场景；三条目标均在 `MAC_002:0x74` 的 `reg_calc 0x17` 停止。页面显示“已载入”表示 WebGAL 已加载转换出的目标场景，并不代表原版这个指令已经实现、画面演出已经还原或跨剧本状态的持久化已完整验证。样片的浏览器逐句与目标场景检查使用 `浏览器测试环境/检查真实选项分支.cjs` 并设置 `CROSS=1`。

实际浏览器复测：三条路线分别逐句匹配 125、108、96 行（包括分支结束提示），每条都确认正确的目标 `.txt` 场景被加载并显示目标场景文字；页面脚本错误为 0。两个可选 Live2D 文件的 404 单列。目标显示此前一度失败：旧命令写入 `changeScene:./game/scene/...`，而解析器会再次添加目录；Vite 对错误路径返回 HTML 的 200，单看 HTTP 状态造成假通过。现生成 `changeScene:文件名.txt;`，检查同时校验目标路径、内容类型与实际显示文字。测试截图和声音听感不能由无头播放证明。

`浏览器测试环境/检查选项分支存读档.cjs` 在隔离浏览器上下文中选择“道歉”，在首句快速存档，推进到下一句后快速读档恢复首句；再次保存并刷新页面后，选择“继续游戏”也恢复首句。该检查覆盖 WebGAL 样片的位置恢复，不证明尚未接入的原游戏状态、调用栈或全局解锁已经持久化。

新增 `选项跨剧本状态样片`：选择后把本次静态假设轨迹中已修改的状态按字节写入 WebGAL 的普通变量；三条分支在目标场景分别显示原表选择编号 0、1、2，浏览器逐句检查及场景状态核查均通过。状态字节只覆盖已执行的写入，起始状态仍假设为零，条件分支仍在转换时按假设选择，不是完整 MAC 动态解释器。

独立构造脚本 `浏览器测试环境/检查状态存读档与跨场景.cjs` 测试值 1 存档、改为 2、读档恢复 1；刷新后“继续游戏”仍为 1，再改成 2 并切换场景后仍显示 2。此测试证明 WebGAL 普通变量的样本持久化及跨场景传递，不证明原游戏的所有状态和全局解锁语义。
