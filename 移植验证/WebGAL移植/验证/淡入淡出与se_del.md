# `fade_start` / `fade_wait` / `se_del`：解码、记账与新卡点 `time_wait`

本文接着 [`SE段解码.md`](SE段解码.md)。那里停在 `0x358` 的 `fade_start`；本轮把
`fade_start`/`fade_wait` 与紧随其后的 `se_del` 解出并接进转换器，`MAC_000` 开头因此
从 38 句推进到 **74 句**，停在 `0x730` 的 `time_wait`。全部地址可由
`转换器/淡入淡出证据.py` 从 ELF 现场重算，产物是 `数据/淡入淡出ELF证据.json`。

**后续（同日）：** `time_wait` 与 `ext_goto` 已接入；新产物从 `0x730` 继续，
在 `0x73C` 跳到 `MAC_001.bin 0x0C`，停在 `MAC_001.bin 0x58` 的 `reg_calc 0x17`。
本页表格中的 `_越0x730_v74` 仍是当时 74 句的产物，保留为历史证据；
新停止点见 [`等待与跨剧本跳转.md`](等待与跨剧本跳转.md)。

## 1. 结论摘要

- `fade_start`（`0x68`，8 字节）处理函数 `0x0011E398`：读方向位 `ip[1]`、时长操作数
  `u16@2`、颜色字 `u16@4`；把颜色写入 `gp-0x6D44` 起的全局对象，并把 `ip += 8`。
- `fade_wait`（`0x69`，4 字节）处理函数 `0x0011E5B0`：轮询过渡对象 `+0`，等于 1 才
  前进；原程序会阻塞到淡入淡出结束。
- `se_del`（`0x3B`，4 字节）处理函数 `0x0011D0E8`：`ip[1]` 是通道号，转调
  `0x12D478(通道)` 停止该通道声音，然后 `ip += 4`。
- `MAC_000` 开头在 `0x358`–`0x71C` 之间共有 **14 组**淡出/淡入、**28** 条
  `fade_*` 事件；`0x72C` 的 `se_del` 是通道 2。
- WebGAL 侧没有“全屏渐变到指定颜色后更换画面”的单条命令，因此淡入淡出只写进报告
  `fade_events`，`webgal.mapped=false`，不生成语句；样片不会出现原版的白色/黑色过渡。
- 新停点 `0x730` 的 `time_wait`（`0c017800`）尚未解码，这是下一条真正未实现的指令。

## 2. `fade_start` 的参数与写入位置

以开头第一组为例：`0x358` 的 `68 80 1e 00 ff 0f 00 00`。

| 字段 | 原字节 | 含义 | 证据 |
|---|---|---|---|
| `ip[1]` | `0x80` / `0x7F` | 最高位选择过渡表项 `+0`/`+4`；低 7 位沿用上一次的索引 | `lbu 1($s0)` `0x0011E44C`；`beq $a1,0x7F` `0x0011E460`；`sh` 写入 `0x0011E478`/`0x0011E4AC` |
| `u16@2` | `0x001E` = 30 | 时长操作数，经 `0x115730` 读取；≤0 时钳到 1 | `lh 2($s0)` `0x0011E448`；`jal 0x115730` `0x0011E444`；`slt/movz` `0x0011E458`–`0x0011E464` |
| `u16@4` | `0x0FFF` | 颜色字；低 12 位 `0xFFF` 特判为 RGB(255,255,255) | `lhu 4($s0)` `0x0011E3BC`；`andi 0xF000` `0x0011E3C0`；`beq 0xFFF` `0x0011E3F4` |
| 高 4 位非 0 | `0xF000` | 不复用新颜色，读回上一次存下的颜色 | `0x0011E3C0` 分支 + `0x0011E4BC` 读回 |
| RGB444 展开 | — | `r=(v>>8)<<4`、`g=v&0xF0`、`b=(v&0xF)<<4` | `0x0011E40C`/`0x0011E410`/`0x0011E418` |

过渡表基址 `0x2140F0`，每项 12 字节；首项 `(20, 21, 0)`。方向位 1 取 `+0`、0 取 `+4`
（`0x0011E4CC`–`0x0011E524`）。`+8` 的 `type` 在首项为 0，本轮没有据此分派。

方向命名不是 ELF 里的字符串：证据只证明最高位选择两个表项。产物按同一过渡
“先出后进”的指令顺序，把最高位 1 记为 `fade_out`、0 记为 `fade_in`；这一点列在
证据 JSON 的 `unknowns` 中。

## 4. `se_del`

`0x72C` 的 `3b 02 00 00`：通道 2，转调 `0x12D478(2)`，然后 `ip += 4`
（`0x0011D100`–`0x0011D11C`）。产物把它记进 `se_events`，与其它 SE 指令一样
`webgal.mapped=false`，不生成音频命令。

## 5. 为什么仍然不映射画面

WebGAL 4.6.6 没有“全屏渐变到指定颜色、再更换画面”的单条命令；现有 `setTransition`
只作用于背景/立绘切换，不能表达“先淡出到白色、换背景、再从白色淡入”的两段式过渡。
本轮又不准备伪造时长或颜色，所以只记录 `fade_events`：

- `direction`、`duration`、`color`、`rgb` 都是原字节的解码结果；
- `webgal.mapped=false`，`reason` 写明“只记录、不生成画面过渡”；
- 样片仍使用手工指定的静态背景，`graph_disp` 与淡入淡出都没有还原。

## 6. 新卡点：`0x730` `time_wait`

```
0x730  0c 01 78 00    # time_wait，参数 0x0178
```

处理函数 `0x001192D8` 有 0/1/2 三个状态，`0x001192B8` 起两次 `0x115730` 读取
`lh 2(s1)`，随后调 `0x11FD00`。参数 `0x0178` 与完成条件的语义尚未核实，因此停在这里。
0x734 之后还有 `reg_calc` 与 `ext_goto`（`0x73C`），跨剧本跳转也尚未实现。

## 仍未证实

1. 方向命名（`fade_out`/`fade_in`）由同一过渡的指令顺序推断，ELF 只证明最高位选择表项。
2. 时长单位：`0x001E`=30、`0x0001`=1、`0x005A`=90 原样传给过渡对象 `+8`，未确认是帧还是毫秒。
3. 颜色字高 4 位非 0 时“复用上一次颜色”的机制（是否带 alpha/标志位）未核实。
4. 过渡表项 `+8` 的 `type` 与 `0x109568`/`0x17E488` 两个分支的渲染差异未核实。
5. `time_wait` 的参数与完成条件、`ext_goto` 的跨剧本行为均未实现。
