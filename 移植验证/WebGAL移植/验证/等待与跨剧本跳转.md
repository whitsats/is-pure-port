# `time_wait` 与 `ext_goto`：等待、跨剧本跳转与新的停止点

> **2026-11-15 修正：** 本文旧版含 `changeScene:./game/scene/...` 的写法会被解析器重复拼目录，实际无效，应改为 `changeScene:文件名.txt;`。验证不能只看 Vite 返回 HTTP 200，还要核对实际响应内容及目标场景显示。具体见 `验证/真实选项与跨剧本样片.md`。

**结论（2026-11-14）：** `MAC_000.bin` 开头现在从 `0x88` 走到 `0x730` 的 `time_wait`，生成 WebGAL 的 `wait:2000;`，再在 `0x73C` 记录 `ext_goto` 并跟进 `MAC_001.bin` 的 `0x0C` 入口；目标剧本读到 `0x58` 的未实现 `reg_calc` 运算 `0x17` 停止。台词仍是 **74 句**（`0x88`–`0x6C8`），新增 1 条等待；新产物为 `数据/开头程序转换_跨MAC001_至0x58_v74.txt(.json)` 与 `数据/开头片段原字节_跨MAC001_至0x58.json`。开头样片重建在 `开头样片_跨MAC001/`，场景 75 行（74 句台词 + 1 条 `wait`）加提示/分隔，核查 102 句逐句严格相等、55 条语音加载并播放。

**后续（同日）：** 同一剧本内的 `int_goto`（`0x03`）也已接入，见 [`int_goto.md`](int_goto.md)。`ext_goto` 现在可由 `--scene-dir` 生成多场景并在段末写 `changeScene`：真实 `MAC_001 0x51E4` 的 `06000200` 进入 `MAC_002.bin 0x0C`，目标在 `0x74 reg_calc 0x17` 停止；详见 [`int_goto.md`](int_goto.md) 第 4 节。跨剧本 `ext_call`/`ext_return` 仍未实现。

## ELF 证据

证据 JSON：`数据/跳转与等待ELF证据.json`（由 `转换器/跳转与等待证据.py` 生成，记录 ELF SHA-256）。

### `time_wait`（`0x0C`，4 字节）

| 项目 | 结论 | 地址 |
|---|---|---|
| 处理函数 | 命令表 `0x0C` → `0x00119258` | `0x213590` 表项 |
| 模式 | `lbu ip[1]` | `0x001192E0` |
| 时长操作数 | `lh ip[2..3]`，经 `0x115730` 读取 | `0x001192BC` / `0x001192C4` |
| 计时对象初始化 | 写 `+4 = 时长`、`+8 = 当前计时器`、`+0 = 0` | `0x0011FD04`–`0x0011FD10` |
| 计时器 | `*(gp-0x6DE8)` 每帧 `+1` | `0x10DF44`–`0x10DF48` |
| 帧循环调用点 | `jal 0x10DF38` | `0x1132BC` |
| 完成条件 | `elapsed >= duration`；模式 1 且全局 `+0x47C == 1` 时立即完成 | `0x0011FD2C`–`0x0011FD40`、`0x0011FDA0` |
| 状态机 | 状态 0 初始化计时对象并转 1；状态 1 检查完成，完成后 `ip += 4` | `0x0011FD00` / `0x0011FD18` |
| 前进量 | 完成后 `ip += 4` | `0x0011930C`–`0x00119318` |

`0x730` 的原始字节是 `0c 01 78 00`：模式 `1`、操作数 `0x0078 = 120`。按帧循环 60 Hz 换算为 **2000 毫秒**，生成 `wait:2000;`。

**不是已证实的部分：** 计时器递增函数在帧循环的调用点上，但没有实测每帧调用次数（可能受跳帧/暂停影响）；全局 `+0x47C` 的触发条件未核实；模式 0/2/3 的输入/跳过语义未核实。转换器只实现模式 1，其他模式停止，不猜测。

### `ext_goto`（`0x06`，4 字节）

| 项目 | 结论 | 地址 |
|---|---|---|
| 处理函数 | 命令表 `0x06` → `0x001196B8` | `0x213590` 表项 |
| 资源号 | 只读 `lhu ip[2]`；`ip[1]` 未读取 | `0x00119708` |
| 资源号拆分 | 高 4 位组、低 12 位索引 | `0x12D81C` / `0x12D820` |
| 加载 | `0x12D980(style=0, code)` → `0x12D810(code)` | `0x0011970C` |
| 组 0 名字 | 运行时表 + `%s.BIP` | `0x12D850`、ELF `0x270078` |
| 状态机 | 状态 0 只置 1、不读资源；状态 1 读资源并启动加载；状态 2 等待后替换 `ip` | `0x001196D0`、`0x001196EC`、`0x00119708`、`0x00119724` |
| 切换 ip | 把 `ctx+0x44` 结构的 `+0xC` 作为新 `ip`，不是 `ip+4` | `0x00119758`、`0x00119774`–`0x00119780` |
| 目标探测 | `MAC_001.bin` 头部 `09 11 00 60 08 00 00 00`，入口 `u32@8 = 0x0C` | `数据/入口片段.json` / 原文件 |

`0x73C` 的原始字节是 `06 00 01 00`：资源号 `0x0001`，组 0、索引 1。按既有 `MAC_命令表/跨剧本跳转候选.tsv` 的候选规则得到 `MAC_001.bin`（候选原始名 `IS01_2.BIP`），入口 `0x0C`；文件头与入口由原文件复核，候选行也写进证据 JSON 的 `ext_goto_candidate_row`。

WebGAL 侧现在可用 `changeScene` 表达这次跨剧本切换：`convert_chain` 记录目标文件和入口，`--scene-dir` 把每段写成独立场景，并在 `ext_goto` 段末生成 `changeScene:<目标场景>.txt;`。历史产物中的旧路径有误，应重新生成。开头 `MAC_000 0x73C` 的报告仍按原来的单场景产物保留 `jumps` 事件（`webgal.mapped=false`）。两条链路的目标寻址相同，都是组 0、索引到 `MAC_xxx.bin`，目标入口取文件头 `u32@8`。

**不是已证实的部分：** 组 0 的运行时名字表内容、索引到 `MAC_xxx.bin` 的静态对应（沿用候选规则）；`ext_call`（`0x07`）/`ext_return`（`0x08`）与调用栈；跳转后原程序是否重置消息窗/状态块（链式转换只保留同一个 `State`）。`ext_goto` 是多状态加载命令，转换器把状态 0→1→2 视为已完成，**没有模拟加载等待的帧数**；`time_wait` 同样把初始化/检查合并成一次 `wait`。

## 目标剧本上下文

`MAC_001.bin` 从 `0x0C` 到 `0x54` 的已解码指令：

- `0x0C` `msg_view`、`0x10` `msg_wait`、`0x14` `msg_clear`
- `0x18` `msg_mode 6`
- `0x1C` `fade_start`（黑色）、`0x20` `fade_wait`
- `0x24` `graph_disp`
- `0x2C` `file_read`、`0x30` `file_wait`
- `0x34`–`0x54` 的 SE 段
- `0x58` `reg_calc`，运算码 `0x17`（未核实）→ 停止

这一段**没有台词**，所以新产物台词数仍是 74；但 `file_reads`、`se_events`、`fade_events`、`displays`、`state_writes` 都增加了 `script: MAC_001.bin` 的记录。上下文合并进同一报告，`segments` 明确标出两段：

1. `MAC_000.bin` `0x88` → `0x73C`，74 句 + 1 等待；
2. `MAC_001.bin` `0x0C` → `0x58`，0 句。

停止点从原来的 `{MAC_000, 0x730, time_wait}` 变为 `{MAC_001, 0x58, reg_calc}`，原因写明“未核实的 reg_calc 运算 0x17”。

## WebGAL 表达

- `time_wait` 模式 1：`wait:2000;`。WebGAL `Core/gameScripts/wait.ts` 把内容转成 `Number` 毫秒，自动播放也等待；用户点击可提前结束该等待（`blockingNext` 未设置）。原版全局 `+0x47C` 的提前结束没有模拟。
- `ext_goto`：`convert_chain` 写 `jumps`；加 `--scene-dir` 时在父场景末写 `changeScene`，目标无台词时写 `__commment` 记录停止点。
- 目标上下文中的 `msg_*`、`fade`、`graph_disp`、`file_read`、SE 仍沿用既有“只记账、不生成画面/音频”的规则。

## 仍未证实 / 下一步卡点

1. `MAC_001.bin 0x58` 的 `reg_calc 0x17` 已定位到 `0x00118FD0`：全局位表 `0xA98C50`、状态 `G+0x440/+0x4B0`、计数 `0xB1EC20` 与场景表 `0xB25554`。原文的 `0xA98AD0` 是地址计算错误，已于 2026-11-15 修正；详见 [`reg_calc17调查.md`](reg_calc17调查.md)。正式转换器继续拒绝执行。
2. 其后的 `0x60 quick_save`（处理函数 `0x11D888`，读完 `ip[1]` 后 `ip += 4`）与 `0x64 title_disp`（`0x11E6F8`，有计时/标题显示状态）尚未实现；`quick_save` 可能触发存档，`title_disp` 有画面与等待，不能当无副作用跳过。
3. `time_wait` 模式 0/2/3、全局 `+0x47C`、计时器每帧调用次数；`ext_call`/`ext_return`、`int_call`/`int_return` 与跳转后的状态重置。
4. 组 0 运行时名字表与索引→文件名仍未静态证明；目前只用文件头/入口和既有候选表。
