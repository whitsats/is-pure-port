# I’s Pure WebGAL 剧情状态对齐实施计划

**目标：** 玩家从新游戏开始作出选择后，WebGAL 能在运行时维护影响剧情的状态；跨章节、存读档和继续游玩后，后续选项与分支仍与原版已核验的规则一致。

**方案：** 以已提取的 MAC 指令、已核实的状态读写规则和空白卡新游戏状态为依据，优先转换成 WebGAL 的变量、条件、选项和场景命令。WebGAL 无法可靠表达的少量操作，再实现可被存读档管理的扩展；所有未知指令记录来源并阻止将对应路径标记为已完成。

**技术：** Python 转换器及测试、WebGAL 4.6.6、Node/Playwright 无头浏览器、原程序指令的隔离执行和现有内存证据。全部通过命令行操作，不使用 computer use。

## 最新检查：如何批量完成全部剧情脚本

当前进度以[接手顺序](../../WebGAL移植/当前进度_2026-11-15_后续接手.md)为准。4203 已生成至 `MAC_056`，默认路线在真实浏览器到达结束提示，65 个选项点的 170 项已验证汇合。接手优先补当前仍显示日文的 264 条，并验证代表结局路线与晚期存读档。以下为此前的计划和里程碑。

执行进度以[主线剧情图、全组选项接线及终章状态回放](../../WebGAL移植/当前进度_2026-11-15_后续接手.md)为准。候选图与 109 处接线已生成，五种诊断状态回放到达同一终章出口。当前连续可玩边界仍是 `MAC_004:0x1AA8`，下一里程碑是让同一构建从新游戏越过这段特效并连到终章。

2026-11-15 复查时，`新游戏动态MAC004/public` 已从第五组选项的三条分支跨进 `MAC_004`，能显示章节标题并选择 `0xA38` 的两项。现有无头浏览器记录中的三次运行均到达 `MAC_004:0x1AA8 effect_start`。本次复查确认 4197 的场景接口返回真实场景和选项，并重跑 Python 回归，232 项通过。浏览器长路线以已有记录为依据。

逐段编译入口、操作数推导与分支选项解析已经具备。当前生成器仍负责逐点接选项、指定跨剧本目标和复制汇合段。`mac_wiring.py` 记录样片中已有接线。完整构建需把这些边写入同一个生成流程。

1. **先建立全盘剧情图。** 用 `入口片段_扩展候选.json` 作索引，从 `MAC_000:0x0C` 沿顺序、条件两侧、原选项分支和跨文件指令遍历。节点以原剧本和偏移标识，所有跳转检查实际命令边界，并把未解码指令、未知边、已知结束命令和孤立入口记录下来。此阶段给出静态候选图，再用带状态的自动探索判断真实可达性。73 个候选片段共找到四处 `end` 指令，仍需区分真实结局、其他退出方式和未覆盖文件 `MAC_068`。
2. **从图生成一份连续的 WebGAL 游戏。** 复用 `compile_range` 的指令发射与 `read_options` 的表解析。对已确认格式自动生成显示条件、原序号写回、原指令后续入口和跨剧本目标。共用同一节点的场景，让玩家状态在运行时决定走向。遇到全部选项隐藏时保留原版返回值及后续控制流。调用与返回需要保存对应的返回位置。先用已有第五组和 `MAC_004` 前段回归，再贯通一条新游戏至已核实结局的路线。后续复用相同入口覆盖其他结局。
3. **并行补内容索引。** 全段以 v7.4 发布目录 `打盘/mac-v6.afs` 为第一来源，`数据/v74打盘优先对白.tsv` 已解出 24,428 条，标注工程回退及待核。先检查剩余的原槽、字码及控制码，再查旧汇总表。按脚本、偏移和缺口原因出表，先补主线及结局依赖项。语音按已提取文件与原编号成批核对。
4. **按规则处理阻塞。** `MAC_004:0x1AA8` 是当前实跑遇到的第一处障碍，全盘静态候选片段里有 99 条 `effect_start` 和 160 条 `effect_wait`。按参数模式核查哪些状态会被后续剧情读取，再成批接入；这些计数包含尚未证明可达的指令。并行推进与特效独立的选项、跨剧本跳转和结束点。把影响分支的章回进度从编译期影子状态迁至可保存的运行时状态，并按证据处理共享字节和选项位。
5. **用自动化验收全剧情。** 自动遍历已确认的路线和结局，输出每个已知选项的可见条件、原编号、去向及首个阻塞。到达同一位置且影响后续的状态相同，可以合并探索。对关键分歧、存读档和各实际结局，用无头 WebGAL 和隔离原版定点复核。验收以一份可连续运行的构建、所有已确认的分支和结局都有复现路径，以及剩余差异有证据为准。

相关产物见 [动态场景编译与验证](../../WebGAL移植/验证/动态场景编译入口.md) 和 [MAC_004 浏览器核验](../../WebGAL移植/数据/MAC004接续浏览器核验.json)。

## 范围和现状

- 目标是最终让完整游戏从开始走到各结局；本计划只解决其必要的剧情状态和分支，不抢做安卓打包、原版界面或画面美化。
- 空白卡的新游戏 57 位进度表初值为零，前两次置位已与原版隔离测试对上；全通关卡全 1 是另一种进度状态。这不代表整个游戏的所有状态已对齐。
- `转换器/mac_state.py` 已实现经原程序核查的字/位读写、部分计算和条件；字与位可能共享字节，不能分别保存成互不关联的变量。
- 现有三组选项样片的路径部分预先展开，第三组选项使用按路径预先算出的值；它证明 WebGAL 的条件界面可工作，**不证明完整剧情状态已在运行时动态计算**。
- 既有浏览器存读档测试证明 WebGAL 基础能力；不代表原游戏所有必要变量、调用栈或跨周目状态已经被保存。
- 第六组选项后的 `effect_start/effect_wait` 尚未完整对齐。诊断模式省略副作用，仅供定位，不可作为等价结果。

## 第一阶段：先确定哪些状态影响剧情

1. 以现有 `数据/入口片段_扩展候选.json` 为起点，建立条件和选项对状态的读取清单，以及 `reg_calc` 等已知写入点；记录剧本、指令偏移、原始字节、读写方式和已知证据。
2. 沿读取点向前追踪可能的写入，区分剧情分支、跨周目进度、画面/音频或用途未明。处理位/字共享地址，未解析指令、间接读写和 `MAC_068` 单列；**静态候选不是可达性或完整覆盖证明**。
3. 先以第三组选项为贯穿样例：`MAC_000:0x1C` 初始化字 `0x602C = 20`；首组选项对应的实际模拟路径中可得到 20 或 21，第二组选项路径中可得到 19、20 或 21。`MAC_003:0x24A4` 先写 `0x6010 = 1`，`0x24AC` 判断 `0x602C < 21`，否则 `0x24BC` 写 `0x6010 = 0`；`0x24C4` 第一选项按 `0x6010` 决定显示。
4. 验收：形成可追溯清单，能解释上述 19/20/21 三种状态如何影响选项；不把变量名称或业务含义未经证实地称作“好感度”。

建议入口：`转换器/mac_state.py`、`转换器/mac_choice.py`、`数据/新游戏首选项真实路径分析.json`、`数据/新游戏第二选项路径分析_拆分修复2.json`。新增分析文件放在 `转换器/`，结果放在 `数据/`；保留已有产物。

## 第二阶段：让状态在 WebGAL 实际运行时变化

1. 给转换器增加可复用的状态输出层：依据原指令在对应剧情位置生成状态读写和条件，而不是把一次离线计算结果写成固定数值。先覆盖已证实的赋值、加减、比较、选项返回值和字/位共享语义；其余操作明确拒绝或单列。
2. 默认采用可跟随 WebGAL 普通存档、快速存档和场景切换的舞台变量。分别设计必要的全局进度及新游戏初始化；不能让“开始新游戏”错误清除跨周目进度，也不能在读档时重新初始化局部剧情状态。
3. 明确 16 位有符号数、溢出、位写入取最低位、字节顺序、位与字的别名关系。不要假定 WebGAL 表达式原生支持所有位运算、取整或溢出规则；逐项验证，不够用时实现最小扩展并确保存档与回溯可恢复。
4. 将前两组选项的返回值及影响 `0x602C` 的真实写入接入运行时，让第三组选项直接读取动态结果；不再根据路径预先设置 `mac_6010=0/1`。
5. 验收：同一套场景从同一起点接受不同选择，运行时得到预期 19/20/21 和显示条件；同一变量在字写入与位读取、位写入与字读取的边界样例上结果一致。

建议修改 `转换器/emit_webgal.py`；必要时新增 `转换器/mac_webgal_state.py` 和 WebGAL 最小扩展。避免替换或清理现有引擎工作区。

## 第三阶段：用原版证据和真实浏览器交叉验证

1. 补充可复现的命令行测试：针对字/位别名、算术边界、条件比较、选项序号及跨剧本写入，比较原程序处理函数的隔离执行结果与转换器计算。未知或环境依赖的行为标明边界，不强行认定等价。
2. 对前述 19、20、21 三类代表状态，使用隔离的原版内存副本或隔离运行实例定点核查相关条件和选项；记录测试入口、初始状态、操作、结果和局限。原版只需核查能区分规则的代表情况，无需人工逐句通关全部路线。
3. 在无头浏览器中从新游戏进入实际转换场景，至少覆盖条件选项显示与隐藏各一条；在选择前后分别快速存档、推进、读档、刷新并继续，检查状态值、显示选项和后续分支。定点入口只用于补充测试，不能冒充从头跑通。
4. 运行 `python -B -m unittest discover -s 移植验证/WebGAL移植/tests -q` 和新增浏览器测试；保留测试命令和结果。原盘、用户 PCSX2 配置及其存档只读；不使用 computer use。
5. 验收：代表状态的原版证据、转换器和 WebGAL 结果一致；读档前后所需变量及选项一致；未覆盖的操作和路径有清单。

## 第四阶段：扩展到完整游戏并处理后续阻塞

1. 按同一机制处理其他影响分支的状态操作和跨剧本跳转。自动探索控制流与状态，以实际程序状态和入口为依据合并可证明相同的探索状态；不要按每个历史选项组合手工创建一份永久分支。
2. 对尚未理解的操作数、随机数、间接跳转和调用/返回，优先判断是否影响剧情。只影响可简化演出的部分可以明确简化；可能改变分支或结局的部分必须补证据或保留为阻塞。
3. 对 `MAC_004:0x1AA8 effect_start` 与后续 `effect_wait`，先确认本路径会写入的状态是否被后续剧情读取，再决定如何保留必要状态并简化特效。不得把诊断模式输出当作原版等价。
4. 将状态正确的转换并入同一个连续游戏工程，同时接入对应中文、已核验语音和画面；WebGAL 自带菜单、存读档、回看和鉴赏优先复用。视频最多接开头和结尾各一段。
5. 最终验收：从新游戏通过不同选择到达各结局；自动验证尽可能多的分支，按风险抽查原版关键节点；中途存读档、重启继续及跨周目进度正确。不能仅凭局部单元测试或一条样片宣布完整。

## 优先顺序

第三组选项条件已通过原处理器的隔离执行和无头浏览器对照。从第三组选定后可存档，读档或刷新后继续至第四组。现阶段的对照范围和剩余检查点见 [最新交接](../../WebGAL移植/当前进度_2026-11-15_后续接手.md#最新交接动态剧情与批量转换)。

恢复后优先把共享场景编译器推广为批量入口，先试编 `MAC_003` 余段和 `MAC_004` 开头。集中处理影响剧情的缺失规则，用同一批测试覆盖所有使用点，再同步抽核原版关键状态、处理特效状态阻塞和接入后续素材。
