# 消息窗节奏：原程序证据与转换规则

**证据文件：** `数据/消息窗ELF证据.json`（由 `转换器/消息窗证据.py` 从 `输出-保护边修复/SYSTEM/SLPM_665.70` 直接生成）。
**转换器：** `转换器/emit_webgal.py --message-window`。
**样片：** `消息窗样片/`（本机 `http://127.0.0.1:4182/`）。

## 1. 已核实的原程序事实

反汇编用 MIPS64 小端（该 ELF 的压栈/取栈是 `sd`/`ld`，用 MIPS32 模式会把 `sd ra,8(sp)` 之类解错）。每条命令的处理函数取自原程序命令表 `0x213590`。

| 操作码 | 名称 | 长度 | 处理函数 | 读手柄 0x2000 位 | 说明 |
|---|---|---|---|---|---|
| `0x60` | `msg_disp2` | 12 | `0x00119D68` | **是**，1 处（`0x0011A324`） | 自带指令状态机（8 项跳转表 `0x00259D90`）与窗口状态分派（10 项跳转表 `0x00259DB0`） |
| `0x12` | `msg_view` | 4 | `0x00119938` | 否 | 读指令第二字节作参数；等待消息窗记录 `+0x18` 为 1 后前进 |
| `0x1A` | `msg_wait` | 4 | `0x0011A960` | 否 | 两段式状态机：先等文字完成检查 `0x124118`，再前进 |
| `0x1B` | `msg_clear` | 4 | `0x0011A9E8` | 否 | 调 `0x122D18` 重置消息窗记录，清 `0x4FC`/`0x4D8`，立即前进 |
| `0x13` | `msg_mode` | 4 | `0x0011A678` | 否 | 参数 5/6 最常见，含义未核实 |

由此得到的结论：

1. **一次玩家推进对应一条 `msg_disp2`。** `msg_disp2` 的处理函数里唯一的手柄判定（`lui $v1,0xc5` → `lw …,0x6508($v1)` → `andi …,0x2000`，位于 `0x0011A324`）在“文字已显示完”的分支上，键位未在真机确认。
2. **`msg_view` / `msg_wait` / `msg_clear` 不读按键。** 它们只检查消息窗/文字完成状态，或重置窗口后立即返回，因此不产生额外的玩家推进。
3. **`msg_view` 的参数在全部 73 个入口片段中只出现过 `3`**（5,789 处），这是转换器只接受 `12030000` 的原因。

## 2. 转换规则

| 原指令 | WebGAL 输出 | 依据 |
|---|---|---|
| `msg_disp2` | 一条 `say`（含 `-VOICE_xxxxx.wav`） | 每条对应一次玩家推进 |
| `msg_view`（参数 3） | 不生成语句，写入报告 `pacing` | 不新增文本、不读按键 |
| `msg_wait` | 不生成语句，写入报告 `pacing` | 同上；WebGAL 的 `say` 已经等文字显示完 |
| `msg_clear` | 不生成语句，写入报告 `pacing` | 下一条 `say` 会替换文本框内容 |
| `msg_mode` 及其它 | **停止转换** | 未核实 |

译文来源固定为 v7.4 原始工程中与剧本、指令偏移对应的最终译文；三版核查表的逐字节对盘结果只作证据保留，不参与选译。

转换器会拒绝以下情况（不会静默跳过）：

- 节拍命令出现在已转换台词之前（无法确认它对应什么停顿）；
- `msg_view` 参数不是 `3`；
- 台词在 v7.4 工程中没有按地址对应的中文、或语音号不在已校验清单内；
- 文本含 `; : | \` 等 WebGAL 语法字符。

## 4. 样片核查结果

`浏览器测试环境/检查消息窗样片.cjs`（无头 Edge，静音）：

- 22 句按剧本顺序逐句出现，每句一次推进；脚本对正文做整句严格相等比对（仅提示行用包含匹配），可发现跳句与错句；
- `VOICE_01124/01125/01126/01127.wav` 均 HTTP 200 并触发播放；
- 无视口脚本错误；仅 WebGAL 自带的 `lib/live2d*.js` 404（本样片未使用 Live2D）。

`python -B -m unittest discover -s tests -v` → 全套 90 项通过（含消息窗规则、ELF 证据与 v7.4 选译用例）。

## 5. 尚未证实 / 已知差异

1. **同屏保留之前的行**：原消息窗是逐行累积还是每句替换，尚未确认；WebGAL 每条 `say` 只显示当前句。推进节奏已对齐，文本框内的“旧行是否还在”未对齐。
2. **`msg_disp2` 的按键位**（`0x2000`）对应哪个实体按键未在真机确认。
3. **`msg_view` 参数语义**：只确认它会写入/等待窗口状态，未确认数值本身代表什么；参数非 3 的情况一律停止转换。
4. **`msg_clear` 后到下一句之间若显示画面**，WebGAL 中上一句文字会短暂停留（没有等价的“只清文字”指令）。
5. 背景、立绘、转场、`msg_mode` 均未实现；样片背景为手工指定。
