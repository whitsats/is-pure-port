## 三、解码规则与验证

### 1. 图块格式（BG / CHR / EV / ETC / BGM）

- 像素流按 **1024px 行宽**切成 32 行高的存储行，每行 32 个 32×32 物理瓦片；
- 每个瓦片四周各有 **1px 镜像保护边**，有效核心 **30×30**（索引 1..30）；
- 部件表坐标为网格单位，**步长 30px**；瓦片号全局连续，部件边界不重置；
- 按头部显示矩形裁剪。

旧规则按 32px 步长拼合会重复绘制保护边，导致耳廓外凸、眼镜框断裂、太阳穴悬空竖线、下颌锯齿。

### 2. 与游戏自带 TIM2 缩略图对照（独立真值）

平均 RGB 差（0–255）：

| 类别 | 旧规则 32px | 新规则 30px |
|---|---|---|
| EV 事件 CG | 29.6–48.4 | **1.00–1.53** |
| BG 背景（宽银幕带对位） | — | **0.98–1.66** |
| CHR 半身像 | 20.7–35.6 | **3.5–20.4** |

33 个抽样条目全部改善、0 个变差。EV/BG 已达约 1/255 色差，等同像素级一致。

### 3. 结构自洽

- CHR 尺寸严格二分：879 张 640×448 + 594 张 140×130，与既有“全身/半身”划分一致；
- BG 140 张、EV 68+1 张全部 640×448（EV 特例 640×896）；
- 全量 1473 + 280 + 138 + 40 + 118 条目解码 **0 失败、0 空白图**。

### 4. TIM2 子格式（ETC / BGM）—— 依据开源参考实现修正

参考 [`punk7890/PS2-Visual-Novel-Tool`](https://github.com/punk7890/PS2-Visual-Novel-Tool)
的 `src/comFuncs.gd::load_tim2_images`，修正了本作 TIM2 的三处关键点：

1. **CLUT 位于像素数据之后**：`clut_off = (picture_header + header_size) + image_size`，
   而不是常见的“调色板在像素之前”；
2. **调色板需要 unswizzle**：`clut_colors` 为 256/512 且 `clut_color_type` 的 bit7 为 0 时，
   按 `pos = (p & 0xE7) | ((p & 0x8) << 1) | ((p & 0x10) >> 1)` 重排（交换 bit3/bit4）；
3. **调色板可能是 16 位 RGBA5551**（512B）或 32 位 RGBA8（1024B），需分别处理。

修正前后差异极大：修正前 ETC 的 8bpp 贴图只能看到“形状对但颜色乱”的碎片；
修正后可直接读出 `Screen Setting / Sound Setting / Message & Font / Auto Control / Et cetera`、
`SHORT CUT / OPTION / FILE EDIT / LOAD / QUICK LOAD / SAVE / CG MODE / MOVIE / CONTROL MANUAL`、
角色名牌 `IORI / ITSUKI / IZUMI / AIKO`，以及 TAKARA TOMY、CRIWARE 标识与 PS2 手柄图示。

> 该修正只影响带调色板的 TIM2（ETC 的 8bpp/4bpp 贴图）。BG/CHR/EV/BGM 的 TIM2 为 32bpp 直读，
> 不含调色板，因此它们的输出不受影响。

### 5. PSS 视频音频（以下为修复前历史排查）

> 2026-11-14 复查结论：**原先的「已破解」判断是错的**，当时的验证指标（相邻样本差/RMS）
> 对「低通噪声」也会给出低值，不能证明是正常音频。改用「谱平坦度」对比后确认 MV 音频是噪声。
> 全部已确认的字节结构、已排除的假设与未解问题，统一记录在
> 《[项目进度总览.md](项目进度总览.md)》第 4.1 节；在此不再重复。

已知的确定事实（供后续排查）：

```
MPEG-PS 私有流包 (stream id 0xBD) 的 payload:
  [0:17]   封装头：83 80 0a 21 + 2 字节递增字段 + 2 字节递增字段 + ff×6 + a0 00 00
  [17:49]  【仅首包】SShd 块：'SShd' + size=0x18 + codec=1 + rate=48000 + ch=2 + block=512 + 8×ff
  [49:57]  【仅首包】SSbd 块头：'SSbd' + body_size(18,329,600)
  [57:]    【仅首包】音频数据；后续包数据从 17 开始
```

- 数据量 18,329,600 B / 95.47 s = **192,000 B/s**，与「48kHz × 2ch × 16bit」完全吻合，
  因此**体积上必须是未压缩 PCM**（ADX / SPU2 ADPCM 的数据率只有这个的 1/4~1/3）；
- 但按 16bit/小端/2ch 解读后：相邻样值相关 0.897、L/R 相关 0.956（结构上像音频），
  谱平坦度却高达 **0.47**（正常音乐 0.04–0.17，语音 0.30），自相关无音高周期，
  波形是「有包络的低通噪声」→ **样值内容不对**；
- **最强异常线索**：包长只有两种（4090 / 4076），减去 17 字节头后为 **4073 / 4059，都是奇数**，
  即每包的音频数据不落在样值边界上；两种包长的差值恰为 14 字节，成因未明。
