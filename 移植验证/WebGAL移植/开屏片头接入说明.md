# 开屏片头（OP 循环）接入说明

更新时间：2026-11-15。样片目录 `开屏片头样片/`，启动 `运行开屏片头样片.cmd`，地址 `http://127.0.0.1:4195/`。

当前 v7.4 高清移植版已经采用这套片头和标题循环。启动 `运行新游戏打盘高清版.cmd` 后访问 `http://127.0.0.1:4204/`。高清版使用独立存档键 `ISPv74DiscHD01`。

## 效果

原版式开屏，不使用 WebGAL 的 “PRESS THE SCREEN TO START” 落地页，也不经过语言选择页：

打开游戏 → 直接播手机版高清片头 → 播完停在标题界面（背景为片头里的 logo 帧）
→ 停留 `Opening_hold_time`（样片 15 秒）→ 片头从头再播，如此循环。

开始游戏、读档、选项等操作随时打断循环；从剧情 `end;` 或“返回标题”回到标题时，先停在标题界面，再按停留时间回到片头。
标题里的“鉴赏模式”“片头回放”打开时暂停循环，关闭后回到标题继续停留计时。

## 接入正式游戏

`public/game/config.txt`：

```
Opening_video:MV_OP01_phone60.mp4;
Opening_hold_time:15000;
Default_Language:zh_CN;
Title_img:title_op.webp;
Enable_Appreciation:true;
```

- `Opening_video` 放在 `game/video/`；`Opening_hold_time` 单位毫秒，不写默认 15000。
- `Default_Language` 让语言选择页不再挡在片头前。
- `Enable_Appreciation` 打开标题界面的“鉴赏模式”（CG/BGM 鉴赏）；标题出现“片头回放”则只需要 `Opening_video`。
- 不再使用 `Appreciation_Preset`；鉴赏条目只由剧情/影片实际触发。旧的预置脚本保留但本工程不配置、不读取。

标题停留图放 `public/game/background/`，样片的 `title_op.webp` 取自手机版片头 89.5 秒的 logo 帧：从 2400×1080 里裁掉两侧模糊填充（取 `x=428..1972` 的 1544×1080），放大到高 1440 后居中补成 2560×1440。标题按钮样式在 `public/game/template/UI/Title/title.scss`，已按浅色背景改为深色字 + 左侧白色渐变。

没有 `Opening_video` 的工程完全不渲染片头组件，其他样片不受影响。

## 鉴赏（游廊）的数据来源

WebGAL 原生的鉴赏数据存在 `userData.appreciationData`（`cg` / `bgm` 两个数组），由 `unlockCg` / `unlockBgm` 以及 `changeBg` / `bgm` 的 `-unlockname` 写入，并按 URL 去重、持久化到 localforage（按 `Game_key`）。当前工程不再启动时批量预置：正文 EV 在显示时解锁，正文 BGM 在真正起播时解锁；片头/片尾影片在 `playing` 事件里解锁对应的 `EV_OP01` / `EV_END01`。干净档案从空鉴赏开始。

`public/game/appreciation.json` 仍保留为 69 条 CG / 8 条 BGM 的总表，逐条对应工程里真实存在的 `game/background/EV_0000.png` ~ `EV_0136.png`（与 `移植验证/输出-保护边修复/EV/` 的 69 个文件一一对应）。它现在只作资料/缩略图清单，不再作为启动预置：

```json
{
  "cg": [{ "file": "EV_0000.png", "name": "EV_0000", "order": 0, "thumb": "thumb/EV_0000.webp" }, ...],
  "bgm": [{ "file": "IS_Pure_BGM_SE_00136.mp3", "name": "移植版命名・曲目01・SE_00136" }, ...]
}
```

`thumb` 是可选字段：鉴赏列表用它显示，点开全屏仍用 `file` 原图；不填就直接用原图（兼容原有 `unlockCg` 数据）。

### CG 缩略图

原图是 640×448 的 RGBA PNG，69 张共 27 MB，整本一次渲染在安卓上吃不消。现在用 Pillow 生成 `game/background/thumb/EV_xxxx.webp`：宽 576（鉴赏格子实际显示约 576×540，再小会发虚）、WebP quality 82，69 张合计 **1.72 MB**（原图的 6.4%）。

生成脚本是 `移植验证/生成CG缩略图.py`，同时会把 `thumb` 字段写回 `appreciation.json`：

```
python 生成CG缩略图.py                 # 576 宽、q82，重出全部缩略图并写回数据
python 生成CG缩略图.py --width 480 --quality 78
python 生成CG缩略图.py --dry-run       # 只统计体积，不写文件
```

参数不变时重复运行得到的是逐字节相同的 WebP（已用 MD5 核对），可以放心重跑。

原图没有改动也没有删除，点某个条目仍会加载 `game/background/EV_xxxx.png` 原图全屏查看。

### BGM 怎么筛的

原盘 `BGM.AFS` 里是 40 组“404 Not Found”调试占位图，真正的音乐在 `SE.AFS` 的长音频里（`输出-保护边修复/BGM_music/`，42 条 WAV + `清单.txt`）。按清单的谱平坦度判读，其中 8 条是音乐（#136、#143、#145、#146、#148、#149、#151、#152），其余是环境音或待定。

这 42 条里 #134–#153 与 #154–#173 是同内容的两份拷贝：逐对做了 SHA-256 比对，**20 对全部字节一致**（如 #136 与 #156），所以去重后总可用曲目是 22 条。

接入时把这 8 条音乐从 WAV（PCM 48 kHz 立体声，单曲 17–32 MB）转成 160 kbps MP3（合计 21 MB）放进 `game/bgm/`，文件名 `IS_Pure_BGM_SE_xxxxx.mp3` 保留原盘条目号，便于回查；未改动 `BGM_music/` 原文件。

引擎保留 `src/Core/util/coreInitialFunction/appreciationPreset.ts` 作为可选预置钩子，但本工程已从 `config.txt` 删除 `Appreciation_Preset`，因此不会预置任何条目。新增的 `src/Core/util/unlockCgFromAsset.ts` 只把片头/片尾的 `playing` 事件转发到原生 `unlockCgInUserData` 并落盘，不新增第二套状态。

空缓存打开游戏时鉴赏为空；片头真正起播后出现 `EV_OP01`，开始游戏后随正文显示/播放逐步出现正文 CG 和 BGM，第 37 章「我一个人走进了神社。」之后解锁 `EV036`，片尾视频起播解锁 `EV_END01`。

## 原版游廊与 WebGAL 的对应

| 原版标题菜单 | 本工程 | 说明 |
| --- | --- | --- |
| `CG MODE` | 标题“鉴赏模式” | 用 WebGAL 原生鉴赏页；正文 EV 按显示解锁，片头/片尾按影片起播解锁，`EV036` 按第 37 章「我一个人走进了神社。」这一幕解锁。原版相册标志仍有待核实项 |
| `MOVIE` | 标题“片头回放” | 原版鉴赏类菜单里确实有 `MOVIE`（项目文档与 ETC 取字：`SHORT CUT / OPTION / FILE EDIT / LOAD / QUICK LOAD / SAVE / CG MODE / MOVIE / CONTROL MANUAL`）。WebGAL 鉴赏页只有 CG 与 BGM 两个分栏，没有影片栏，所以在标题菜单补一个“片头回放”，复用同一条 `MV_OP01_phone60.mp4`（带声音、可跳过，结束回标题继续停留/循环）。END 影片尚未接入，所以“片头回放”只放 OP |
| 音乐鉴赏 | 鉴赏页 BGM 栏 | 原盘存在音乐模式（INIT 调试项 `ミュージック全開放`），但数据里只有 `BGM01…BGM20` 这类槽位名，没有曲名表。WebGAL 鉴赏页接入了 8 首判定为音乐的 SE，名称统一为 `移植版命名・曲目NN・SE_xxxxx`，可切歌、播放、暂停。未接入的环境音/待定曲目不冒充音乐 |
| `SHORT CUT`、`FILE EDIT`、`CONTROL MANUAL` | 未做 | 章节跳转、文件编辑、说明书不属于游廊，也不在开屏/首版范围 |

| `src/Core/util/unlockCgFromAsset.ts` | 片头/片尾 `playing` 时转发原生 CG 解锁 |
| `src/App.tsx` | 挂载 `<OpeningLoop />` |
| `index.html` | 落地页默认 `display:none`（避免 fetch 返回前闪一帧）；解析阶段读 `config.txt`：有 `Opening_video` 就保持隐藏并把文件名交给组件，没有就恢复显示落地页 |

三点实现说明：

- **首帧不留缝**：`index.html` 在页面解析阶段就读 `config.txt` 并写入 `window.__WEBGAL_OPENING_VIDEO__`，React 首次挂载时直接带片头文件起播，不必等组件自己的 axios；配置未读完时先盖黑场。否则标题菜单会以默认样式露 0.6 秒左右（已用采样脚本复现并修掉）。
- **片头配置直接读 `./game/config.txt`**，不用 `userData.globalGameVar`。引擎会把 config 写进本地存储，之后 `getStorage()` 又整份恢复，改文件名或改停留时间后会读到旧值。
- 片头循环开启时同时把 `isShowLogo` 关掉，避免 WebGAL 的 Logo 过场与片头叠加。

## 行为细节

- **自动播放**：先尝试带声音播放；被浏览器策略拦截时立刻**静音起播**，画面不中断、不出现“点击开始”空屏，只显示一行“片头已静音播放，点击任意处开启声音”。玩家第一次点击（或按键）只恢复声音，不跳过片头、不重头播放；之后再点才跳过片头。
- 片头播放期间暂停标题 BGM（`#currentBgm`），回到标题界面再恢复，避免和片头音轨重叠。
- 片头结束才补一次“进入引擎”的点击，让标题 BGM 和音量设置生效。
- 呼出菜单/回想/鉴赏时自动退回标题界面，回来重新计时。
- 片头文件加载失败时停止本局循环并记录错误，不会黑屏卡死。
- 标题界面按钮沿用 WebGAL 现有标题菜单（开始、继续、选项、读取、鉴赏模式、片头回放、退出）；剧情选项用 WebGAL 原生 `choose`。

## 限制

1. **浏览器自动播放策略**：无用户交互时带声音播放会被拦截，此时是静音起播（画面照常），点击即有声。只有在浏览器连静音自动播放都拒绝时，才会退回到“点击开始 / 播放片头”的一层。Electron 或安卓 WebView 可用 autoplay 策略放开，直接带声音进片头。
2. 20:9 片头和片尾使用窗口视口播放。20:9 显示成片全宽，19.5:9 和 16:9 等比铺满并裁去部分侧边填充。比 20:9 更宽的视口保留整幅视频。竖屏时沿用 WebGAL 的旋转或缩放策略。
3. 60fps 解码与 65 MB 体积对低端设备有压力，安卓端可重编码更低码率。
4. 鉴赏列表已改用 576 宽的 WebP 缩略图（整本 1.72 MB），但全屏查看仍是 640×448 原图；要上更高分辨率素材时，应同步重出缩略图。
5. 标题 BGM 仍是 WebGAL 自带 `s_Title.mp3`，尚未换成原版标题曲（原版标题曲未确认是哪一条）；END 影片没有接。
6. 鉴赏 BGM 只放了 8 首判定为“音乐”的曲目；`BGM_music/` 里另有环境音与“待定”条目，没有拿它们充数。MP3 是 160 kbps 有损转码，要无损可改回 WAV（体积约 4 倍）。
7. 样片剧情是占位文本，只用于验证开屏流程；正式剧情仍由转换器接入。
