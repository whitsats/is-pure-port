# 动态场景编译入口与批量试编（2026-11-15）

上一版把第三组选项之后的场景写死在 `MAC_003:0x24D0–0x34AC`。本轮把它改成按
「剧本 + 起始偏移」编译的入口，并加入阻塞分类，使批量试编 `MAC_003` 余段和
`MAC_004` 开头成为可重复的命令行操作。

## 入口

`转换器/mac_runtime_scene.py`：

| 函数 | 作用 |
| --- | --- |
| `compile_range(script, start, end=None, words=None, strict=False)` | 编译区间，遇到第一个阻塞项停在它之前，返回 `Stop`（类别 + 源偏移 + 原字节） |
| `scan_blockers(script, start, end=None, words=None)` | 对同一区间静态扫描**所有**阻塞项并按类别汇总，不执行状态、不生成行 |
| `collect_operands(commands, start)` | 从区间实际引用推导要跟踪的字/位；字与其它跟踪项共用地址时显式报错 |
| `continuation()` | 既有区间；输出与旧实现逐字节一致（SHA-256 `79eaa304…949863`，326 行 / 64 条语音） |

命令行 `转换器/编译动态场景.py`：

```powershell
# 编译 MAC_003 第四组之后，直到下一个需要玩家输入的选项
python -B 转换器/编译动态场景.py --script MAC_003.bin --start 0x34B8 \
    --scene 数据/动态场景_MAC003_0x34B8.txt --report 数据/动态场景编译报告_MAC003_0x34B8.json

# 只做分类扫描
python -B 转换器/编译动态场景.py --script MAC_004.bin --start 0x0C --scan-only \
    --report 数据/动态场景编译报告_MAC004_0x0C.json
```

两个输出文件都拒绝覆盖已有结果。生成的场景行与 `sim` 无关：每条状态写入都
带 `mac_<操作数>` 变量名，报告里保留源偏移，便于回查原剧本。

## 阻塞类别

`choice / cross_script / effect / title / if_parameter / reg_calc / dynamic_wait /
translation / unresolved_target / opcode`，每类在 `CATEGORY_NOTES` 里有说明，
报告里给出计数、样例偏移和样例原因。跳转目标落在区间外时按
`unresolved_target` 截断，避免生成悬空标签。

## 乘除取余

`MAC_003` 余段用到运算 3（乘）与 4（商）。WebGAL 的 `setVar` 由
angular-expressions 求值，实测支持 `%` 且与 R5900 一样向零截断，因此：

- 乘：`((a)*(b))%(65536)`，再由既有 `±65536` 回绕进有符号 16 位；
- 商：`((a)-((a)%(b)))/(b)`，即先减去余数再整除，等价于向零截断；
- 余：`(a)%(b)`；
- 位运算 6/7 仍显式拒绝：该引擎对 `&` 报词法错误、对 `|` 报语法错误。

浏览器核验（`数据/算术核验向量.json` → `node 检查动态剧情状态.cjs --arithmetic`，
无头 Edge，`http://127.0.0.1:4193/`）10 个向量全部与 Python 的 R5900 模型一致：

```text
7 op3 6 = 42        30000 op3 2 = -5536      -300 op3 300 = -24464
7 op4 2 = 3         -7 op4 2 = -3            7 op4 -2 = -3        -32768 op4 -1 = -32768
7 op5 2 = 1         -7 op5 2 = -1            7 op5 -2 = 1
```

## 第五组选项接线（`MAC_003:0x5A44`）

### 解析依据（全部来自原始盘）

| 项 | 值 | 来源 |
| --- | --- | --- |
| 指令头 | `72 03 07 60 14 77 00 00 …` | `输出-保护边修复/MAC/MAC_003.bin` 偏移 `0x5A44` |
| 选项数 | 3 | 指令字节 `+1` |
| 结果寄存器 | `0x6007`，先由 `09 00 00 60 07 60 00 00` 拷到 `0x6000` 再逐项比较 | 指令 `+12..+20` 与后续三个 `if` |
| 选项表指针 | `0x7714` | 指令 `u32@+4`；表在后文区之前 |
| 三项记录 | 文本指针 / `field1` / `field2` = `0x00050001`、`0x00060001`、`0x00070001` | `mac` 选项表 12 字节记录 |
| 显示条件 | 三项都是 `field2 & 0xFFFF = 0x0001` | `mac_choice.plan_choice` 求值 → 可见项 `[0,1,2]`（零状态下即如此，不随前序路径隐藏） |
| 分支目标 | `0x5A90`、`0x5EB4`、`0x626C` | 每项 `if` 的目标地址；三者都是命令边界 |
| 选项文本 | `いいかげんにしろ！`→`你适可而止！`、`冗談だろ？`→`开玩笑吧？`、`…………`→`…………` | 盘上 cp932 文本 + `数据/选项v74地址核查.tsv` 唯一匹配（生成器逐字核对） |

解析复用 `MAC_批量选项分支.inspect`（与第一至四组同一套布局检查）与 `mac_choice.plan_choice`，
没有新增猜测常量。

### 接线方式

`生成新游戏第五选项样片.py`（拒绝覆盖已有样片）从 `新游戏动态第四选项/public` 复制后：

1. `mac003_to_fourth.txt` 原结尾“当前版本到此为止”改成 `changeScene:mac003_fifth.txt;`；
2. `mac003_fifth.txt` = `0x34B8→0x5A44` 的 `compile_range` 结果（1632 行）+ 第五组 `choose`（3 项）+ 每项写 `mac_6007`、`mac_entry` 后进入共享分支场景；
3. `mac003_fifth_branches.txt` = 从 `0x5A90` 编译的分支共用场景（编译 268 行 + 3 行分派 + 2 行边界共 273 行，48 条语音），开头用 `mac_entry==0/1/2` 分派到 `0x5A90/0x5EB4/0x626C` 三个 `label`（由 `compile_range(extra_labels=…)` 生成）；
4. `start.txt` 初始化 27 个状态字（`OPERANDS` ∪ 区间推导）与 `mac_entry`；
5. 只复制场景实际引用的语音（新增 168 + 48 条的并集）。

`compile_range` 新增 `extra_labels` 参数，用于把选项表的分支目标变成标签（这些目标不是
`if`/`int_goto` 的目标）；非命令边界会显式报错。

## 跨剧本接续：`MAC_003:0x6790` → `MAC_004:0x0C`

| 指令 | 原程序 | 生成 / 记录 |

   再回来处理特效，这样两条分支可以在特效边界前后都有可停点。
3. 除法只在 Python 模型与浏览器定点向量上对照过；原程序同一位置的运行时数值
   仍未用 PCSX2 实测比对。
4. 状态写入只覆盖被跟踪的字/位；字与其它操作数共用地址时仍拒绝（共享字节模型
   未完成）。
5. 第五组只验证了「道歉 / 走廊 / 青梅竹马而已 / 我得说说她」这一条前序路线；
   其余 32 条可见前序路径尚未逐条在浏览器走到第五组（选项可见性与前序状态无关，
   但 `0x6026/0x602A/0x602C` 等计数会不同，分支内的条件仍可能分叉）。
