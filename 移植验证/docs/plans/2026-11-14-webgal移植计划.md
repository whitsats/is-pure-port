# I’s Pure WebGAL 移植实施计划

> **2026-11-15 用户最新澄清：** 最终目标是整部汉化游戏可正常运行和到达相应结局；单路线只作为开发里程碑。优先使用 WebGAL 已有菜单、存档、回看、鉴赏和常见演出，不要求复刻 PS2 界面与内部格式；视频最多开头和结尾各一段。具体能力、差距及验收以 [原版与 WebGAL 功能对照](../../WebGAL移植/原版与WebGAL功能对照.md) 和 [项目范围与优先级](../../WebGAL移植/项目范围与优先级.md) 为准。

> **2026-11-15 用户确认的范围调整：** 游戏本体与连续游玩优先；WebGAL 原生存读档和后续鉴赏功能优先复用，PS2 记忆卡界面、原存档格式和非关键功能不作为首版前置。需要保留影响剧情的状态，对不确定的进度副作用做明确标记。具体以 [`WebGAL移植/项目范围与优先级.md`](../../WebGAL移植/项目范围与优先级.md) 为准。

**目标：** 以 WebGAL 为底座，将已汉化的 PS2 游戏素材和剧本逐步转换为可在浏览器运行、最终可安装到安卓的独立游戏应用。

**架构：** 离线工具从现有 MAC、中文台词及素材输出中提取带原始偏移和可信度的中间数据，再转换为 WebGAL 场景、资源及变量。WebGAL 负责对白、画面、音视频、交互和存读档；少量无法直接表达的原游戏行为再评估扩展。先验证一个真实片段，再扩大到完整游戏。

**技术：** Python（已有提取工具与离线转换）、WebGAL / WebGAL Script、HTML/JavaScript、后续安卓 WebView 打包。APK 不需 PS2 模拟器，但内部使用 WebView；本计划不处理导入 PS2 记忆卡存档。

**状态：** 这是实施计划，不代表样片或转换器已经完成。WebGAL 本身不认识 MAC 指令，也不能保证现有结果自动构成完整游戏。

## 与原先 1～3 步的对应关系

原先说的三项都继续做，只是电脑上的验证程序采用 WebGAL：

1. **修正剧本解析器** → 下文阶段 2。入口表、命令边界和数据区域必须重新区分；已有静态研究只是基础，尚未完成解析器修复。
2. **确认跨剧本加载** → 下文阶段 4 第 3 项。前期会继续利用已有的静态候选映射，但在资源组、调用和返回得到证实前，不能宣布跨剧本加载完成。
3. **做电脑剧情验证程序** → 下文阶段 1 和阶段 3。阶段 1 只是用手工素材测试 WebGAL 的界面和存档；阶段 3 才接入真实剧本及分支，并与原游戏对照。前者不能作为后者完成的证据。

顺序上先快速跑通阶段 1 的基础环境，再做阶段 2 的解析修正与阶段 3 的单剧本片段；推进到跨剧本连续播放时必须完成阶段 4 的对应验证。不同部分可以并行研究，但不能用手工样片代替剧本转换，也不能用未确认的跨剧本映射当成最终规则。

## 可复用的现有资料

- `移植验证/输出-保护边修复/MAC/`：原剧本；同目录下 `BG/`、`CHR/`、`EV/`、`ETC/`、`VOICE/`、`SE/`、`BGM_music/` 和 `MV/` 为已提取素材。视频应选带声音且经过验证的版本，核对 `移植验证/MV音频修复/验证记录.md`。
- `移植验证/MAC_文本语音/00_IS01_1.BIP.tsv` 等：行号、语音号、日文及中文；仍需确认行号与具体指令的对应，不能只按行顺序当成完整剧情。
- `移植验证/MAC_命令表/`：命令长度、候选选项映射、显示条件和跨脚本跳转等；这些大多是静态结果，运行时对应关系尚未完全验证。
- `移植验证/MAC_跨剧本跳转与入口.md`：入口表在 `0x08`；普通剧本和调试剧本入口不同，旧线性扫描把表项当过指令。`移植验证/MAC_条件求值.py` 只支持已研究的条件子集。
- `移植验证/MAC_33候选引用结构.md`：`graph_disp` 的 12 字节记录结构已有证据，字段与实际图像编号的关系仍不明确。

## 设计原则与工作目录

1. 在 `移植验证/WebGAL移植/` 下创建独立工程、转换器、清单和验证结果；原盘、汉化包、已输出的保护边修复素材保持原样。外部工具固定明确版本并记录来源及许可证，不覆盖现有文件。
2. 先使用 WebGAL 原有场景、选择、变量、存档和媒体功能；只有样片证明不够用时才增加扩展。先比较“离线转为 WebGAL 脚本”和“自定义解释器桥接”，优先选择能正确处理原脚本分支且能持久化状态的较简单方案。
3. 每条转换记录保留原文件、偏移、原始操作数、转换结果及可信度。未知指令明确报错或标注，不能静默跳过后声称剧情完整。
4. 自动生成内容与人工确认内容分开；语音缺失、中文缺行、资源未匹配和不可达分支输出清单，不用猜测的图片或状态伪装为已还原。

## 阶段 1：引擎样机和素材对接

**交付：** 本地浏览器可打开的 WebGAL 样机，不代表游戏脚本已移植。

1. 核对 [WebGAL 官方仓库](https://github.com/OpenWebGAL/WebGAL) 的稳定版本及安装要求，记录版本、提交号、许可证；在 `WebGAL移植/engine/` 使用独立副本。检查 Node 与包管理器环境，按该版本官方文档启动；不要影响现有项目。
2. 在 `WebGAL移植/样片/` 建立最小项目，手工放入 3～5 行已提取的中文、一张确认来源的画面和一段确认对应的语音；标注本阶段是手工验证，并非剧情已自动还原。
3. 在电脑浏览器测试点击推进、中文显示、音量、播放语音、返回标题、存档与读档；记录步骤和结果于 `WebGAL移植/验证/样机验证.md`。
4. 验收：离线启动步骤可复现；浏览器关闭重开后，样机存档可恢复位置和场景；不通过时先排查版本、资源路径、浏览器存储，避免进入批量工作。

## 阶段 2：剧本入口与中间数据

**交付：** 一个可检查的、保留原偏移的剧本中间表示和入口修复验证报告。

1. 新建 `WebGAL移植/转换器/mac_reader.py`，复用 `MAC_命令表提取.py` 的原程序命令长度；分别标记头部、入口表、已确认指令、数据区域，不把 `0x08` 表项解析成命令。先支持已知入口形式，不猜测表长或未覆盖代码。
2. 新建 `WebGAL移植/tests/test_mac_reader.py`：用真实普通剧本检查第 0 入口 `0x0C`，用 `MAC_063/064/065/069` 检查不同入口；验证引用越界、未知长度、无法确认边界时明确报错。运行 `python -m unittest discover -s 移植验证/WebGAL移植/tests -v`，记录结果。
3. 生成 `WebGAL移植/数据/mac_ir.json`：每项含文件、偏移、操作码、原始参数、候选目标、关联文本与证据状态；未知字段保留原值。中文与语音通过文件、行号、原始引用联合核对，重复或歧义输出 `WebGAL移植/验证/文本映射异常.tsv`。
4. 重新统计有效指令和固定跳转，排除入口表等数据；核对已有 4,651 条 `if` 与 753 条 `int_goto` 的统计范围及边界，保留无法确认的文件单列。验收：样本的文本、语音号和偏移能回查原文件；不能确认的部分不标为通过。

## 阶段 3：真实剧情与选择样片

**交付：** 一段来自真实剧本、至少含一个选择和两条可验证分支的 WebGAL 样片。

1. 选择 `MAC_001.bin` 的 `0x3878` 三选项作为已知候选，结合 `MAC_命令表/选项分支静态映射.tsv` 和显示条件表，确认该段中文、前后上下文及可用画面、语音；若中文选项或素材映射不明确，在样片中明确标记待核实，不凭空翻译为正式结果。
2. 新建 `WebGAL移植/转换器/emit_webgal.py`，只转换该片段已确认的文本、选项、已验证跳转和条件。WebGAL 标签带源偏移，转换报告列出未支持操作码；对状态依赖选项，不假设状态默认为零。
3. 核验 0/1/2 与实际界面选项、跳转目标的关系；已有静态假设是 `0x38C4 / 0x3C2C / 0x40B8`，但只有与原游戏逐项对照后才能标记已验证。无法获得原游戏画面时，保留为未验证，不影响完成独立的静态测试。
4. 验收：正常选项进入各自预期段落；存档、退出、读档后，当前选项及游戏变量恢复正确；浏览器控制台无未处理错误。记录样片具体范围、可验证证据、缺失内容及原版差异。

## 阶段 4：画面、声音、跨剧本

**交付：** 可连续游玩的较长片段，演出与原版逐项对照。

1. 从样片附近的 `file_read` 和 `graph_disp` 出发，追踪资源组、条目与已提取图片的对应；建立 `WebGAL移植/数据/资源映射.tsv`，记录图层、坐标、透明度和验证依据。未确认的 `graph_disp` 字段保持未知。
2. 根据对照结果接入背景、人物、CG、图层、渐变、音效、BGM 和视频。声音按实际资源编号配对；视频选已修复音频版本，END 听感和约 50–101 ms 的录屏偏移继续标记待确认。
3. 查证资源组 0 与 `MAC.AFS` 的关系，再实现 `ext_goto` 等已验证切换；`ext_call` / `ext_return` 的调用栈、状态和异常单独验证，不能根据命名推断全部语义。
4. 用固定记录逐场对比原游戏与样片：台词顺序、中文、语音、图像构图、选项、状态、BGM、转场和存读档。差异写入 `WebGAL移植/验证/原版差异.tsv`，注明阻塞项、证据和复现步骤。

## 阶段 5：安卓样机、完整转换和发布前验证

1. 用 [WebGAL 安卓模板](https://github.com/OpenWebGAL/WebGAL-Android) 建立单独工程 `WebGAL移植/android/`，记录源码版本、构建依赖和包信息；先打包含样片的测试 APK，在真实手机检查横屏、触摸、返回键、声音、视频、存读档及重启恢复。
2. 样片通过后，以中间数据和映射清单扩大转换，按剧本和指令类型生成覆盖报告；存在未知控制流或资源关系的片段保持未完成状态，优先核对真实游戏主线，调试脚本不作为首版必需内容。
3. 验证多周目、分支条件、各结局、全局解锁、鉴赏、文本回看、快进/自动、存档恢复与版本升级。对大量语音和图像做安卓实际加载和体积测试，根据实测决定压缩、预加载和资源分包方式。
4. 首版验收：目标路线可从头通关；选项和结局经原版对照；无静默跳过未知指令；安卓离线启动、存档恢复正常；已知差异、未验证路线与素材说明随构建记录保留。

## 关键风险与决策点

- **不是一次转换就能完成：** 画面资源、状态变化、跨文件调用和部分演出仍在研究；如果 WebGAL 脚本无法准确表达已确认的行为，再比较扩展引擎与保留 MAC 解释器两种方案。
- **存档一致性：** 若自定义解释器承担状态，必须把脚本位置、变量、调用栈和场景状态接入 WebGAL 的存读档与回溯；不能只保存对白行号。WebGAL 自带存档与原 PS2 记忆卡格式无直接兼容关系，本期不做导入。
- **资源和版本：** 中文表并非覆盖所有文本；具体文本版本、缺失率、图片对应和音画同步按样片实际核验。工具、WebGAL 代码及素材都需要记录来源与版本，避免误把旧输出当最终成果。
- **平台定位：** 安卓是独立安装应用，网页内容运行在 WebView 中；需真机验证音频自动播放、后台恢复、存储与性能。

## 下一个实际动作

先执行阶段 1：核对 WebGAL 版本并建立能存读档的本地样机；同时固定一个真实片段及其文本、素材和不确定项，随后开始阶段 2 的入口修复。完成样机后再决定转换器与 WebGAL 的具体衔接方式。
