# 状态字、条件与 reg_calc：从 ELF 到可运行的转换

> **2026-11-15 更新：** 位写入已按 `0x1157F8` 原指令实现并对照验证：使用写入值最低位，0 清位、1 置位；状态位与状态字共享底层字节。9 次读取、4 次字写入和 7 次位写入与隔离运行的原 MIPS 指令一致，证据见 `数据/快照状态读写指令对照_含位写入.json`。旧记录以此为准。

本文件记录转换器新增的“状态 + 条件”这一层是怎么从 `SLPM_665.70` 里读出来的、哪些结论有地址可查、
哪些仍然只能由实机确认。证据 JSON 是 `数据/状态字ELF证据.json`（由 `转换器/状态字证据.py` 现场反汇编生成，
每条结论都带地址；生成时会核对处理函数与命令表，对不上就报错）。

## 1. 已证实的部分

### 1.1 状态字在哪、怎么编码

| 结论 | 地址 | 依据 |
| --- | --- | --- |
| 操作数编码：`kind = raw & 0xC000`（`0x4000` 字、`0x8000` 位、其余立即数），`bank = raw & 0x2000`，`index = raw & 0x1FFF` | `0x00115730` 起的 `andi` 掩码 | 反汇编里出现的掩码正是 `0x1FFF/0x2000/0xC000/0xFFFF` |
| 字：bank0 在 `G + index*2`，bank1 在 `G + 0x220 + index*2`；位：`G + bank*0x220 + 0x200 + index/8` 的第 `index%8` 位 | 同上 | 分支链 `beql/bnel` 的落点 |
| 写入用 `sh`（16 位），与读取同一套算术 | `0x0011585C`、`0x0011586C` | `operand_write` 的 stores 字段 |
| 既非 `0x4000` 也非 `0x8000` 的编码（包括 `0xC000`）直接当立即数：`b 0x1157ec` + `move $a1, $a0` 返回符号扩展的 16 位原值 | `0x00115758`–`0x0011575C`、`0x001157EC` | 入口处 `sll/sra 16` 已把 `$a0` 符号扩展，因此 `0xFFFF` 读作 `-1`，`0xC001` 读作 `-16383` |
| 状态基址是 `*(gp-0x6D44)`，与分派器缓存的是同一个指针 | `0x00114B90`（`sw ... -0x6d44($gp)`） | `state_init.vm_init.reached_from` |

因此 `0x600E` = bank1 字 #14（`0x600E & 0x2000` 置位、`index = 0x00E`），落在 `G + 0x220 + 28 = G + 0x23C`；
`0xA01A` = bank1 位 #26（`G + 0x420 + 3` 的第 2 位）。

### 1.2 初值：进入 VM 时整块状态被清零

- 分派器 `0x00114B90`（`sw` 缓存 `gp-0x6D44`、`jr` 按状态字跳表 `0x002595E0`）的状态 0 落在 `0x00114BB0`，
  它在第一条 `jal 0x1151b8` 进入 `0x001151B8`，后者在 `0x001151E0` 调 `0x001FBB84`，
  参数为 `(*(gp-0x6D44), 0, 0xD38680)`；被调函数具备按 8 字节展开复制的特征（`dsll`+`or`），
  即 `memset(状态块, 0, 0xD38680)`。
- 结论：**执行到这里时，整块状态为 0**；`0x600E` 在没有任何写入时读到 0。
- 仍未证实：这段清零是否每次进入剧本都执行；读档是否恢复这块状态。
  静态代码无法断定，已列入 JSON 的 `unknowns`，本轮不据此做任何“跨剧本保留状态”的假设。

### 1.3 `if`（操作码 `0x02`）

- 处理函数 `0x001187D8`；指令 16 字节：参数 `ip[1]`、目标 `u32@4`、左 `u16@8`、右 `u16@10`、
  比较码 `ip[12]`、连接字节 `ip[13]`。
- 比较表 `0x00259D00`，前 6 项语义：`0 ==`、`1 !=`、`2 <=`、`3 >=`、`4 <`、`5 >`（6/7 是按位与/或，尚未使用）。
- 跳转路径 `0x001189E0–0x00118A20`：条件成立（`s2==1`）时 `ip = 脚本基址 + 目标`，否则 `ip += 16`。
- 参数字节 8/9 走另一套按 8 字节记录扫描的分支（`0x0011892C`/`0x00118980`），**未核实**，转换器遇到即停止。
- 同一剧本的 `int_goto`（`0x03`，`0x00119590`）已接入：`ip = script_base + u32@4`，按命令边界跟进并记录 `int_gotos`；真实 `MAC_001 0x3B94` 路径见 [`int_goto.md`](int_goto.md)。

### 1.4 `reg_calc`（操作码 `0x09`）

- 处理函数 `0x00118CD8`；指令 8 字节：运算码 `ip[1]`、目的/左操作数 `u16@2`、右操作数 `u16@4`。
- 运算表 `0x00259D20` 已核实并接入的项：
  `0` → `0x00118D58`（`dest = right`）、`1` → `0x00118D70`（`addu`，`dest = left + right`）、
  `2` → `0x00118D80`（减法，`dest = left - right`）、`3` → `0x00118D90`（R5900 三操作数
  `mult $a1,$s1,$s0`，`dest = left * right`）、`4` → `0x00118DA0`（`div` + `mflo`，商，向零截断）、
  `5` → `0x00118DB8`（`div` + `mfhi`，余数，符号随被除数）、`6` → `0x00118DD0`（按位与）、
  `7` → `0x00118DE8`（按位或）、`0x0E` → `0x00118E88`（把 `ip+4` 的 16 位有符号立即数写入目的操作数）、
  `0x0F` → `0x00118EA0`（`addu`，与运算 1 相同）。
- `3` 的原始字节 `18 28 30 02` 在普通 MIPS 反汇编器里显示为非法/三操作数 `mult`，因为 R5900 使用
  `rd` 字段作为结果寄存器（`$a1,$s1,$s0`）；证据 JSON 保留原始字节，避免把“反汇编器不支持”误写成“无此指令”。
- `4`/`5` 的除数为 0 时原程序在 `0x00118DAC`/`0x00118F2C` 走 `break`；转换器抛 `UnsupportedCommand` 并停止，
  不把除零当 0 或跳过。
- 尚未实现：`8`/`9` 读写剧本字节/半字、`0x0B`/`0x0C` 写剧本字节/半字、`0x10` 跳转、`0x12` 随机、
  `0x13`–`0x16`，以及已单独调查的 `0x17`。遇到这些仍显式停止。
- **0x17 已单独调查：** 它分派到 `0x00118FD0`，读取并设置全局位表 `0xA98C50`；`G+0x440` 写入编号，`G+0x4B0` 写入旧位值；全部相关位已置位时处理场景表并可能设置 `0xA98D10`。该条于 2026-11-15 纠正旧文对位表地址、延迟槽和分支方向的误判。正式转换器仍拒绝执行；见 [`reg_calc17调查.md`](reg_calc17调查.md)。
- 写入目标是“位”时按 `0x115870–0x115934` 的读改写执行；写入值只取最低位，且与状态字共用字节地址空间。
- 本轮把旧证据 `数据/状态字ELF证据.json`（仅 0/1/2）移存为 `数据/状态字ELF证据_0至2运算.json`，
  再由 `转换器/状态字证据.py` 重新生成主文件；`supported_operations` 现在包含上述 10 项。

## 2. 真实输入上的结果

### 2.1 `MAC_000.bin` 开头（`0x88` 起）越过 `0xAC`

- `0xAC` 原字节 `02000000 D0000000 0E600000 01000000`：`if` 参数 0，目标 `0xD0`，左 `0x600E`、右 `0x0000`、比较码 1（`!=`）。
- 执行记录（见 `数据/开头程序转换.txt.json` 的 `conditions`）：`lhs_value = 0`（无人写过，取清零值），
  `0 != 0` 不成立 → **不跳**，继续执行 `0xBC` 的 `reg_calc`。
- `0xBC` 原字节 `09000E6001000000`：运算 0（赋值），`0x600E = 1`（`state_writes` 记录 `before 0 → after 1`）。
- `0xC4/0xC8/0xCC` 的 `msg_view/msg_wait/msg_clear` 记入 `pacing`（`text_since_clear: false`，因为 `0xA8` 已经清过屏）。
- 停止点：`0xD0` `msg_mode`（`13050000`，参数 5），理由“未转换的指令”。这是**下一条真实阻塞**，不是跳过。

产物：`数据/开头程序转换.txt` + `.json`（含 `conditions`、`state_writes`、`initial_state`、`state_evidence`），
以及 `数据/开头片段原字节_MAC000.json`（`0x88`–`0xD0` 共 10 条指令的原字节，由 `转换器/导出片段原字节.py` 生成）。

### 2.2 `MAC_013.bin` 的条件分支片段（`0x6294` 起）

这段被选作“条件真的改变走向”的实证，转换结果 23 句、14 条语音，两次 `if` 都成立：

- `0x62AC`：`0xA01A`（bank1 位 #26）`== 0` → 跳到 `0x62DC`，跳过 `0x62BC/0x62C8` 两句与 `0x62D4` 的 `int_goto`。
- `0x639C`：同一条件再次成立 → 跳到 `0x6508`，跳过 `0x63AC–0x63E8`（一贵的三句等）。
- 停止点：淡入淡出接入后越过 `0x6550`，停在 `0x6580` 的 `time_wait`；片段仍是 23 句。
- **前提**：这一段从剧本中间开始，转换时按“状态全零”执行，所以两次条件都取了“位 #26 未置位”的分支。
  在真实游戏里位 #26 是否已置位（例如之前看过另一支）无法由静态代码断定；若已置位，会显示另外两句并改走 `int_goto`。
  样片里的提示行写明了这一点。

产物：`数据/状态分支片段_MAC013_v74.txt` + `.json`（生成于淡入淡出接入前，23 句、停在 `0x6550`；译文按地址取 v7.4。旧文件 `数据/状态分支片段_MAC013.txt` 保留为规则变更前的证据），语音校验 `数据/语音校验_MAC013_语音.json`，
原字节 `数据/状态分支片段原字节_MAC013.json`（`0x6294`–`0x6550`，83 条）。

### 2.3 消息窗节拍规则的放宽

上一轮为了不凭空生成停顿，规定“节拍命令前没有台词就停止”。本轮证据表明 `msg_view/msg_wait/msg_clear`
既不新增文本也不读手柄（唯一读 `0x2000` 的是 `msg_disp2` 的 `0x00119D68`，位于 `0x0011A324`），
所以 `msg_clear` 之后再来一轮节拍只是原版的消息窗动作，转换器改为**逐条记入 `pacing` 并标注 `text_since_clear: false`**，
不再当作停止条件。`msg_view` 参数不是 3 时仍然停止。

> 开头已经继续往前：`0xD0 msg_mode` 与 `0xD4 graph_disp` 的语义、以及新的停点，见
> [`验证/消息窗与画面指令.md`](消息窗与画面指令.md)。本节只描述状态/条件层当时的结果。

## 4. 仍然未证实的部分（不做假设）

1. VM 状态 0 的清零是否每次进入剧本都执行；读档是否恢复这块状态。
2. `reg_calc` 运算码 8/9、0x0B/0x0C、0x10、0x12、0x13–0x16 的语义；0x17 的运行时位表/场景表已单独调查但仍缺运行时数据。
3. `if` 参数字节 8/9 的分支形式。
4. 状态位的业务含义及新游戏初值（底层读写规律已验证，见顶部更新）。
5. `int_call`/`int_return` 的调用栈与返回；`ext_call`/`ext_return` 仍无真实 `ext_call` 样本。
6. 状态数组真实边界（`index` 掩码 `0x1FFF` 与 bank 间距 `0x220` 不一致），当前脚本未越界。
7. `0x600E` 在实机上的运行值是否与本轮“开头读到 0”一致（取决于第 1 条）。

以上都写进了 `数据/状态字ELF证据.json` 的 `unknowns`，转换器遇到依赖它们的指令会停止并记录原因。
