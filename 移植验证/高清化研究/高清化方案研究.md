**选型建议**

- 只要求「不拉伸」→ **普通2** 即可，但只用到 64% 屏幕，且仍是 640 插值，偏糊。
- 要「高清 + 满屏 + 不变形」→ **最优解**（推荐）：97% 屏幕利用率，画质来自 ×4 超分母版。

- 竖屏模式 → **方案4**（竖屏重构，见第 5 节），横竖屏可由引擎按屏幕方向选择共存。

## 1. 「无损高清化」的定义与实测

「无损」在放大场景下有严格矛盾：**只要像素变多，就必然要决定新像素从哪来**。
本报告把「无损」拆成三层，逐层给出实测数据，供你选口径。

### 1.1 三层含义

| 层级 | 含义 | 做法 | 实测 |
|---|---|---|---|
| **A. 严格逐像素无损** | 每个原像素变成 N×N 完全相同色块，回采后与原图逐像素一致 | NEAREST ×N | 回采 PSNR = **∞（99.0 dB 封顶）**、SSIM = **1.0000**（数学恒等） |
| **B. 感知无损** | 内容/构图/颜色不跑偏，观感更清晰；允许补充合理细节 | AI 超分（ESRGAN/CUGAN） | 回采 PSNR 21–34 dB、SSIM **0.92–0.99**；锐度提升 20–120% |
| **C. 编码无损** | 不因格式损失颜色/透明 | PNG + RGBA | alpha 通道回采 PSNR 39–55 dB（16bit 量化误差级） |

### 1.2 关键实测（回采 = SR 结果用 BOX 缩回原尺寸再比对）

| 样本 | NEAREST×4 | LANCZOS×4 | ESRGAN-v3 ×4 | RealCUGAN ×3 |
|---|---|---|---|---|
| BG_0218（背景） | PSNR ∞ / SSIM 1.000 | 38.9 / 0.996 | 29.4 / 0.958 | 27.9 / 0.940 |
| EV_0126（事件 CG） | ∞ / 1.000 | 40.2 / 0.996 | 30.7 / 0.963 | 31.0 / 0.957 |
| CHR_0000（全身立绘） | 49.2 / 0.999 | 35.5 / 0.975 | 33.6 / 0.989 | 27.3 / 0.969 |
| CHR_0452（140×130 半身） | 71.4 / 1.000 | 31.1 / 0.988 | 29.1 / 0.983 | 28.1 / 0.977 |

> 说明：NEAREST 的 CHR 回采不是 99 分，是因为「完全透明区域里的 RGB 是垃圾值」，BOX 回采会对这些垃圾值取平均；
> 只看不透明区域（alpha>0）时是恒等的。

### 1.3 结论

- **想要「严格无损」→ 只能用 NEAREST ×N**，代价是放大后呈块状（尤其非整数倍显示时更明显），不能算「高清化」。
- **想要「高清化」→ 必须选 B+C**：AI 补细节 + 母版级保证（等比/不裁/alpha/PNG）。
- 本方案采用 **B+C**，并把「严格无损模式」保留为批量脚本的可选项（见第 6 节）。

## 4. 手机适配：等比系数表（不拉伸的唯一算法）

设目标屏幕宽 `W`、高 `H`（横屏），BG 画面 640×280：
**等比系数 `k = min(W/640, H/280)`**，BG 显示为 `round(640k) × round(280k)`，剩余高度用背景填充。

| 机型比例 | 分辨率 | 等比系数 | BG 显示尺寸 | 剩余处理 |
|---|---|---|---|---|
| 16:9 | 1920×1080 | 3.000× | 1920×840 | 上下各 120px 填充 |
| 19.5:9 | 2340×1080 | 3.656× | 2340×1024 | 上下各 28px |
| **20:9** | **2400×1080** | **3.750×** | **2400×1050** | **上下各 15px（几乎不可见）** |
| 16:9 1440p | 2560×1440 | 4.000× | 2560×1120 | 上下各 160px |
| 20:9 1440p | 3200×1440 | 5.000× | 3200×1400 | 上下各 20px（⚠ 需 ×5 母版） |
| 21:9 | 2520×1080 | 3.857× | 2469×1080 | 左右各 25px |
| 竖屏 20:9 | 1080×2400 | 1.688× | 1080×472 | 需重构，剩余 1928px 背景填充 |

> 因为母版是 ×4，**只要显示系数 ≤ 4 就是「缩小采样」**（质量最优）；3200 宽的 1440p 机型需要 5×，
> 用 ×4 母版显示会做 1.25× 放大（略软）——后续可补 ×5/×6 母版。

### 4.1 横屏推荐方案：BG 满宽 + 上下背景填充（`手机模拟/横屏_2400x1080_BG满宽.png`）

- BG 640×280 等比放大 3.75× → 2400×1050，居中；
- 上下各 15px 用 **BG 顶/底行的平均色**填充（实测几乎看不出接缝）；
- 立绘按高度等比放到 0.82H 靠右；对话框叠在下方；
- 屏幕利用率 **≈97%**（对比原构图方案只有 64%）。

**效果见**：`手机模拟/横屏_2400x1080_BG满宽.png`（2400×1080 实尺寸图，放大可看清 HD 质感）。

### 4.2 对照方案：保留原构图、两侧留边（`手机模拟/横屏_2400x1080_原构图留边.png`）

- 640×448 整幅等比缩放到高 1080 → 宽 1543，两侧各黑边 428px；
- 优点：构图/站位/文字位置与原版一致，实现最简单；
- 缺点：**浪费约 36% 屏幕宽度**，且画面偏小。

### 4.3 竖屏方案（需重构，`手机模拟/竖屏_1080x2400_*.png`）

BG 640×280 等比铺满宽度后只有 1080×472，占屏幕高度 20%，所以必须重构布局：

```
┌──────────────┐
│  背景填充区   │  ← 纯色/镜像/模糊（三选一）
├──────────────┤
│  BG 作画窗    │  ← 640×280 等比 → 1080×472，不裁剪
├──────────────┤
│   立绘（等比） │  ← 全身立绘按高度等比缩到 ~0.52H
├──────────────┤
│   对话框      │  ← 引擎原生绘制文字（不要用图片文字）
└──────────────┘
```

三种背景填充（**都作用于背景填充层，不改素材本体**）：

| 方式 | 文件 | 适用 |
|---|---|---|
| 纯色渐变填充 | `竖屏_1080x2400_纯色填充.png` | 最轻量；用 BG 顶/底行色做渐变 |
| 镜像延伸 | `竖屏_1080x2400_镜像填充.png` | 保留画面氛围，无拉伸 |
| 模糊填充 | `竖屏_1080x2400_模糊填充.png` | 观感最“现代”，注意 GPU 成本 |

> 竖屏方案本质是「界面重设计」，不是素材处理问题；建议横屏优先，竖屏作为可选模式。

## 5. 「背景填充」的三种做法（供引擎侧实现）

| 做法 | 说明 | 是否改变素材 | 成本 |
|---|---|---|---|
| 边缘色填充 | 取 BG 顶/底行（或四边）平均色，做纯色/线性渐变 | 否 | 极低 |
| 镜像延伸 | 把 BG 画面镜像翻转后接着铺，填满剩余区域 | 否（不改像素比例） | 低 |
| 模糊铺底 | BG 等比放大到区域宽度后高斯模糊，作为底层 | 否（底层装饰） | 中（可预烘焙成图片） |

**禁止做法**：把 640×280 分别按宽/高不同比例拉伸去凑屏幕 —— 会让人物和背景明显变形。

脚本：`高清化研究/脚本/批量超分.py`


### 关键设计（对应你的三条要求）

1. **不污染素材**：只读 `输出-保护边修复/`，输出到 `高清化研究/母版-×4/<类别>/`；原素材目录零写入。
2. **不拉伸**：只调用整数倍模型（`-s 4`），且**校验输出尺寸必须严格等于输入 ×4**，否则判失败并删除产物。
3. **无损优先**：
   - 纯色/极简图（如 BG 的 5 张测试色块）**不走 AI**，改用 NEAREST ×4（数学上逐像素无损）；
   - 其余走 AI，但逐张做**回采质检**（BOX 缩回原尺寸比 SSIM），低于 0.90 的图剔除、不写入；
   - 输出 PNG + RGBA，alpha 通道原样保留。
4. **可断点续跑**：已存在的输出跳过；质检日志追加到 `母版-×4/质检日志.csv`。

### 质检规则

| 检查 | 阈值 | 目的 |
|---|---|---|
| 输出尺寸 == 输入 ×4 | 必须 | 防模型倍数错/截断 |
| alpha 均值偏差 | ≤ 2 | 防 alpha 被破坏 |
| RGB 均值偏差 | ≤ 12 | 防整体变色（x4plus-anime 崩坏案例） |
| 输出唯一颜色数 | > 16 | 防输出纯色/空白 |
| 回采样 SSIM（不透明区） | ≥ 0.90 | 防内容跑飞 |
| 纯色源特判 | 输出唯一色 ≤ 64 | 纯色源应保持纯色，不加噪 |

## 7. 风险与注意事项

1. **UI 文字**：AI 超分会轻微改变字形（笔画末端、字间距）。若 UI 文字是贴图且要求绝对还原，
   建议 **UI 交给引擎原生绘制**（矢量字体/9-patch），只对非文字 UI 美术件做超分。
2. **纯色测试帧**：BG_0000/0002/0004/0006/0008 是黑/白/红/绿/蓝测试色块，**不是美术素材**，
   管线已特判为整像素放大（不浪费 AI，也不会被加噪）。
3. **抖动（dither）**：PS2 原图有抖动噪点，AI 会把它抹平成平滑渐变 —— 观感更干净，但**不是逐像素还原**。
   若要求「原汁原味」，需要选严格无损模式（NEAREST）。
4. **1440p 机型**：3200 宽需要 5×，×4 母版会被放大 1.25×（略软）。可后续补 ×5/×6 母版（体积约 2.5 倍）。
5. **半身像 140×130**：×4 = 560×520，1080p 够用；1440p 下若显示尺寸 >520px 会吃紧，可单独跑 ×6。
6. **EV 竖图 640×896**：×4 = 2560×3584，正常处理，注意不要按 640×448 假设去裁。
7. **未验证项**：尚未在真机上跑过；竖屏方案只是布局概念图，不涉及引擎实现。
