# MV 音频修复与验证记录

日期：2026-11-14。输入为项目现有的三段 PSS 与无声 MP4；本目录为独立输出，没有修改原盘或原视频。

## 修复了什么

1. 旧脚本用 `find(00 00 01 bd)` 后仅把搜索位置移到 `i+1`，因此会在一个已有 PES 包的内部继续搜索。开场 OP 在文件偏移 `0xD3023` 恰好出现这样的字节组合，被误当作一个长 743 字节的音频包，导致旧脚本多计一包并把伪数据拼入音轨。新脚本沿 MPEG-PS 顶层包的长度依次前进，不在包内部搜索。
2. `SShd` 标明的本作音轨参数是 PCM16LE、48 kHz、两声道、交错块长 `0x200`。数据是 512 字节左声道、512 字节右声道交替排列；需要先拼接完整音频流，再按块交错回普通立体声 WAV。PES 包在奇数位置切分并不意味着需要填充。

可复用脚本：`提取并合成.py`。它检查顶层 MPEG-PS 边界、PES 私有流标记、SShd/SSbd、声明长度、每包时间戳和音视频首个 PTS；遇到不匹配即报错，不会静默补数据。它只支持本次确认的音频类型，现有输出不会被覆盖。

## 游戏实际录屏对比

使用独立的 PCSX2 副本、BIOS 副本和记忆卡副本，在静音扬声器的情况下录制游戏音画；原模拟器设置和存档未挂载。临时录屏及隔离环境已依用户要求清理；录屏音频为有损 AAC，因此当时不要求与 WAV 逐样本相同。

`比对录屏.py` 将候选 WAV 的单声道混音与录屏 AAC 解码后做归一化相关性匹配：

- OP 在第 2、8、30、60、80 秒的声音，与原游戏录屏对应位置相关系数分别为 **0.988、0.969、0.966、0.961、0.949**；五处相对偏移一致到单个 48 kHz 样本。
- 另将录屏与 WAV 的左右声道分别比较：OP 第 8 秒，录屏左声道与 WAV 左/右声道相关系数为 **0.977 / 0.172**，录屏右声道与 WAV 左/右声道为 **0.187 / 0.977**；第 30、60、80 秒正确声道相关系数也均约为 0.95 以上，支持左右声道未交换。
- LG 在第 0.2、1、2 秒的声音，相关系数分别为 **0.987、0.991、0.992**。
- 录屏中 OP 的匹配画面与音频相比晚约 **50–101 毫秒**（9 处画面抽样；原视频约 29.97 fps、录屏约 59.94 fps，存在帧取样误差）。这证明录屏比较存在一个小的视听偏移，但尚不能判断来自录制链、模拟器运行时还是游戏；不应把录屏偏移当作原始文件必须调整的时间。
- END 尚未通过游戏结局实录或人耳试听独立核验，当前依据是相同格式、严格包边界、连续长度和全片 PTS 自洽。

本次输出采用原 PSS 的首个音视频 PTS 同步关系，**没有强行加入录屏中观察到的偏移**。仍建议实际试听三段，并观察 OP/END 的歌词、对白和画面配合。

## 已输出的文件

`../输出-保护边修复/MV/` 下每段都有：

- `MV_*.wav`：48 kHz / 16 bit / 双声道无损 PCM；
- `MV_*.mp4`：既有无声 MP4 的 H.264 视频流加 256 kbit/s AAC；
- 本目录 `校验/MV_*_校验.json`：包数、时间戳与原 PSS 的 SHA-256。

三段合成视频的视频包 SHA-256 逐包与原无声 MP4 相同，没有重新压制画面。AAC 解码后分别抽取一秒与对应 WAV 对比，LG/OP/END 的音频相关性为 `0.9995 / 0.9930 / 0.9980`，匹配偏移均为 0 个样本。AAC 是有损编码，因此 WAV 可作为后续重新编码的母版。MP4 使用 `-shortest`，音轨结尾可能比原 WAV 短约一帧 AAC；完整音轨保留在 WAV 中。

## 复现

在项目目录安装 Python 的 `numpy`；合成 MP4 还需要 PATH 中可用的 `ffmpeg`。从本目录运行，指定一个尚未使用的输出目录：

```text
python 提取并合成.py --mux --output 输出_再现
python test_pss.py
python 比对录屏.py "自己录制的游戏视频.mp4" --stem MV_OP01 --reference "输出_再现/MV_OP01_音频候选.wav"
```

`比对录屏.py` 另需 `scipy`。它比较的是声音内容，不单独证明全片视觉对口型同步。
