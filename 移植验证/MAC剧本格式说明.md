# MAC.AFS 剧本格式说明（反汇编结果）

日期：2026-11-14。针对 `MAC.AFS`（74 个剧本）的字节码结构分析结果。

> **后续结构勘误：** [MAC_33 候选引用结构](MAC_33候选引用结构.md) 发现 `0x33` 后可能有指向 12 字节记录表的 u32。下文“文本区之前全是指令”“其余都是 4 字节指令”及 256 类操作码统计应视为旧假设，可能混入了指针和数据记录；功能语义仍待运行时验证。

> **原程序命令表新发现：** 主 ELF 中已定位包含 120 个名称及长度的分发表；`0x33` 为 `graph_disp`，`0x3A`–`0x3F` 为音效相关命令，并已找到实际选项和跳转样本。详见 [MAC 原程序命令表与分支验证](MAC_原程序命令表与分支验证.md)。下文有关“解释器未在主 ELF 找到”“255 种命令未知”的表述是旧结论。

## 一、容器结构

```
MAC.AFS（ISO 偏移 192,346×2048，共 1,081,344 字节）
├─ 头：'AFS\0' + 条目数(u32)
├─ 条目表：每项 8 字节（偏移 u32、长度 u32）
├─ 数据区：各条目为 LZSS 压缩的剧本
└─ 元数据表：位置由 (条目表之后) 的 meta(u32)/metalen(u32) 给出，
             每条 48 字节，前 32 字节为文件名（如 IS01_1.BIP、SCRIPT01.BIP、STARTUP.BIP）
```

74 个条目名称示例：`IS01_1.BIP … IS16_3.BIP`（剧情）、`SCRIPT00-02.BIP`、
`STARTUP.BIP`、`SHORTCUT*.BIP`、`APPEND.BIP`、`DBG_*.BIP`（调试用）。

## 二、单个剧本布局

解压后分为两段：

```
[0 .. text_start)   指令区
[text_start .. EOF) 文本区（连续的 cp932 字符串，NUL 结尾）
```

- `text_start` = 所有文本指针的最小值；
- 文本里 `%K` = 换行、`%P` = 翻页（原作者工程文件即用 `{}` 包裹这类控制符）。

## 三、指令格式

**每条指令 4 字节**：`[op][p1][p2][p3]`（op 为操作码，p1..p3 为参数）。

**文本指令（op = 0x60）是 12 字节的特例**：

```
60 00 00 00 | 文本指针(u32) | 行号(u16) | 语音号(u16)
```

- 文本指针是剧本内绝对偏移（指向 cp932 文本）；
- **行号**在每个剧本内从 0 递增，跨 256 自动进位（低字节在操作码位置）；
- **语音号**：`0xFFFF` = 无语音；否则**直接就是 VOICE.AFS 的条目号**
  （实测最大值 12,789 = VOICE.AFS 条目数 12,790 − 1，这是决定性证据）。

## 四、验证结果（全部量化）

| 校验项 | 结果 |
|---|---|
| 指令区是否恰好衔接到文本区 | **74 / 74** |
| IS01_1 的 71 个文本锚点（来自原作者 BIP 清单） | **71 / 71 命中** |
| 文本指针指向的 cp932 文本与原作日文 | 逐条一致 |
| 行号序列 | 每个脚本内严格 0,1,2,…（跨 256 进位正常） |
| 语音号上限 | 12,789，与 VOICE.AFS 条目数完全吻合 |
| 文本记录总数 / 对照 TSV 行数 | 27,398 / 24,876（差额来自 SCRIPT01/02 等菜单脚本） |
| 各章文本数 vs TSV 行数 | 逐章差异 −14 … +11（脚本与对照切分口径不同） |
| 非文本指令总数 | 152,122 条 |

## 五、操作码现状

共出现 **256 个不同操作码**，但**除 0x60（文本）外，其余语义尚未确定**。

高频操作码（附最常见参数）：

| 操作码 | 次数 | 最常见参数 |
|---|---|---|
| 0x00 | 14,202 | (00,00,00)、(F0,00,00)、(00,FF,00) |
| 0x01 | 10,928 | (00,00,00)、(FF,FF,00)、(00,FF,FF) |
| 0x33 | 9,851 | (01,00,00)、(01,01,00) |
| 0x09 | 9,646 | (00,0E,60)、(00,00,60) —— 第三参数恒为 0x60，含义待查 |
| 0x1B / 0x1A | 6,075 / 6,030 | (00,00,00)、(60,E8,03) —— 成对出现 |
| 0x12 | 5,994 | (03,00,00) |
| 0x02 / 0x04 | 5,889 / 4,282 | (00,00,00)、(FF,FF,01) |
| 0x40 | 4,070 | (01,00,00)、(A0,00,00) |
| 0x13 | 3,910 | (05,00,00)、(06,00,00) |
| 0x68 / 0x69 | 3,808 / 3,578 | (7F,1E,00)、(80,3C,00) —— 像时间/持续时间参数 |
| 0x3C/0x3D/0x3E/0x3F/0x3A/0x3B | ~2,400–3,200 各 | 成组出现，像 UI/立绘坐标或显示控制 |

已知线索（未证实）：

- `0x09` 的第三个参数恒为 `0x60`，可能是「相对跳转/宏调用」的标记字节；
- `0x68`/`0x69`、`0x12` 的参数里出现 30/60/0x1E/0x3C 这类数值，疑为帧数或时长；
- `0x3A`–`0x3F` 六条指令成组出现（IS01_1 开头即一组），疑为立绘/图层显示参数；
- 分支/选项指令尚未定位（TSV 中选项文本未单独标注，需要更多线索）。
